## 3. 明确的取舍

| 附件通用建议或参考表现 | 本版处理 | 原因 |
| --- | --- | --- |
| 停用可用中性灰 | 保留低强度红；已结束仍灰 | 项目已有明确业务颜色决定 |
| 工作台四个统计格 | 不强改已有六项概况 | 组合方法可借鉴，数字维度由业务决定 |
| 参考中11px小字和13.5px正文 | 中文正文保留14px | 沿用当前中文与内网环境 |
| 勾选完成、拖动状态 | 不应用于主数据确认 | 保留事务、核对、权限和生效日 |
| 多种看板/日历/时间线视图 | 按真实需求分期 | 控制范围与维护成本 |
| 简单全部即时保存 | 业务走申请、配置保留直接保存 | 对应现有真实契约 |
| 侧边抽屉 | 定义契约，后续按需实施 | 先验证列表，避免双套详情 |
| 参考原生JS/localStorage实现 | 不迁移 | 继续使用HDIP既有技术与服务端规则 |

## 5. 实施时如何使用本表

每个阶段在交付记录中列出本轮覆盖的Q编号、场景编号、变更文件和实际验证。无需为每个编号新建一个测试文件。若某项是后续能力，应标明其数据前提和未实施状态，不用占位按钮假装完成。

完成U1不等于16个场景全部迁移；完成文档编制也不等于通过浏览器或真实业务验收。实施状态应由阶段记录给出。
