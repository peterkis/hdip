# HDIP 各业务场景 UI 调整规范

版本：1.0 · 2026-10-24 · 状态：可交付实施的设计规范，尚未修改应用代码。

适用仓库：`peterkis/hdip`。源码基线固定为 `8c400c49757e2443ceeaa7e1358ba290c786e7c6`。本文件依据该版本实际路由、页面、组件和接口字段编制；它不是对运行中应用的截图验收报告。

## 0. 使用方法与范围

本文件回答“统一视觉语言落到每个页面后，究竟改什么、放在哪里、怎样判断完成”。全站字号、间距、颜色、宽度、行高、控件高度和动效的唯一数值来源为 `docs/design/ui-tokens.md`；本文件引用该总规范的规则，不另建一套尺寸。实施时本文件落位为 `docs/design/ui-scenarios.md`。

| 统一规则 | 本文件使用方式 |
| --- | --- |
| `R-LAY` 布局 | `work` 用于维护列表/台账及复杂申请核对，`document` 用于对象属性/长文字详情，`canvas` 用于图表分析；同页顶栏内容槽、页头、工具栏与数据区外沿共用 frame |
| `R-TYP` 中文文字 | 工作页标题、文档标题、正文、辅助信息、等宽代码分别使用对应文字角色；不能按 Tailwind 默认值误读已被重映射的 `text-xs` |
| `R-COL` 色彩 | 沿用语义色；计划浅黄、停用红、已结束灰，状态使用低强度标签；不把整行停用数据画成错误 |
| `R-ROW` 连续行 | 标准表格、显式紧凑表格、双行工作列表使用不同密度；默认连续行无卡片间隙/外圈阴影，竖线只用于明确的 compare 变体 |
| `R-ACT` 操作 | 页级/分区级/行级动作分层；每个当前任务上下文最多一个主动作；申请核对的提交/确认只在页头提供 |
| `R-DAT` 数据、日期与权限 | 只使用真实返回字段，说明筛选与导出范围，日期含义分开，不从显示状态猜权限 |
| `R-STATE` 状态 | 加载、无数据、无结果、错误、无权查看、已结束/未来记录各自表达 |
| `R-A11Y` 可访问性 | 焦点、名称、对比、点击区、键盘、触控、减少动态效果按总规范验收 |

默认场景布局：SC-02/03/04/06/11/13/15采用 `work`；SC-05/07/14及SC-08/09的详情采用 `document`；SC-08/09的列表与SC-12采用 `work`，内容少时不强行撑满；SC-10采用 `canvas`。SC-03右侧核对目录在净内容宽度达到1040px时使用200px宽度与24px间距，否则改为顶部折叠，不另加900px内层最大宽度。SC-16弹层按表单规范。

以下标记贯穿各场景：

| 标记 | 含义 | 实施边界 |
| --- | --- | --- |
| **现有数据可做** | 已有接口或已取得的数据足以支持 | 可调整版式、文字层级、动作位置、前端状态与可访问性；复用现有业务请求 |
| **接口依赖** | 当前接口尚未提供必要事实、权限或统计口径 | 先确定最小契约，再实现；本轮视觉改造不伪造字段、不逐行补取详情 |
| **后续研究** | 尚未证实必要性的交互能力 | 不作为本轮完成条件，不预先开发通用引擎 |

### 0.1 全部场景共同遵守

1. **对象名称和业务事实先出现。** 代码、ID、维护时间属于辅助信息；代码不可因视觉弱化而变得无法读取、选择或复制。
2. **读取日期、业务期间、记录时间分开。** “已确认”是申请状态，不表示每个变更项都已经在今天适用；未来生效的正式记录保留开始日期。配置字典与申请列表不冒充按全局查看日期过滤。
3. **原有权限和业务动作继续生效。** UI 不靠名称、颜色、行位置或前端身份猜测权限。人员字段沿用后端脱敏结果。
4. **工作列表与对照表分工。** 变更申请适合双行摘要列表；需要跨行比较的主数据保留表格。列很多时允许表格局部横向滚动，不统一改成卡片。
5. **动作靠近作用对象。** 页级动作在页头右侧，分区动作在分区标题右侧，单条关系的动作在该行尾部；危险或低频动作放入明确的“更多”菜单或原有独立入口。
6. **主数据变更与配置保存分别表达。** 部门、服务单元、任用、归属、任职、外部编码登记与解释等业务变更走草稿→提交→确认。分类方案/分类代码、来源系统/来源字典是已有的直接保存配置，不额外套申请流程。
7. **没有证据不补事实。** “未登记负责人”不改成“空缺”；矩阵中的未登记不改成“未开展”；没有归属不推断院区；代码同名不自动代表同一对象。
8. **保持轻量范围。** 不新增 HR 岗位/编制/职级、资质办理、临床授权、排班业务。原 P2 名单导入仍与 I1 跨系统人员身份对应分开；本轮 UI 不启动其中任何一个新阶段。

### 0.2 统一的状态与连续性验收

以下为每个场景的共同验收项，场景末尾另列专项项：

- 首次载入用与最终布局相近的骨架或轻加载说明；不短暂显示“0 条”“无人”“没有数据”。错误不能渲染成空列表。
- 区分初始无数据、筛选无结果、无权限、请求失败、失效链接。每种状态提供与原因对应的一个明确下一步。
- 仅图标按钮有名称；可操作名称使用链接或按钮；键盘焦点可见。整行增强点击不得吞掉行内链接、复选框或文本选择。
- 文字截断以可见空间为依据。重要说明、判定依据和错误原因可通过点击/展开读取，不只靠鼠标 `title`。
- 返回列表时恢复搜索、筛选、排序、视图与滚动位置；对象详情的当前标签页可通过 URL 恢复。只保存必要的页面状态，不在 URL 暴露敏感信息。
- 窄屏先收起侧栏，页头动作换行，搜索独占一行，标签页横向滚动。长表格只在表格区域滚动；不能为避免横向滚动把中文正文缩小。
- 表单取消回到触发处；保存成功按现有业务去向进入申请或关闭配置弹窗。失败保留输入，不连续弹重复 toast。

**读取状态接入（2026-10-25，U3R-03）**：前两条已在下列入口按 R-STATE（`ui-tokens.md` 第 9 节）落实并走查——SC-04 部门、SC-06 服务单元、SC-08 主体、SC-09 院区、SC-12 分类方案、SC-11 编码台账（普通、批量裁决、编码明细弹层）、SC-13 人员名册、SC-15 部门任职（负责人一览与台账同一读取）、SC-02 申请列表（同键刷新失败保留结果）、SC-10 组织总览（按区块依赖）、SC-05 / SC-09 / SC-08 详情附属区（人员与职务、下属单元、运营关系图）与六个详情页主读取（403 / 401 / 404 / 失败分开）。组织变更向导的依赖读取留 U3R-04；返回恢复、日期作用说明留 U3R-05。

## SC-01 应用外壳、导航与全局日期

### 当前基线

来源：[`components/layout.tsx`](https://github.com/peterkis/hdip/blob/8c400c49757e2443ceeaa7e1358ba290c786e7c6/web/src/components/layout.tsx)、[`components/shell/nav.ts`](https://github.com/peterkis/hdip/blob/8c400c49757e2443ceeaa7e1358ba290c786e7c6/web/src/components/shell/nav.ts)、[`App.tsx`](https://github.com/peterkis/hdip/blob/8c400c49757e2443ceeaa7e1358ba290c786e7c6/web/src/App.tsx)。

已有暖灰侧栏、分组折叠、面包屑、主题切换、开发期身份切换和全局“查看日期”。默认入口为 `/service-units`。桌面正文实际使用 `lg:px-(--hd-space-64)`；不能把未在这里使用的96px令牌当作当前实际边距。现有分组为“组织与关系”“空间与场所”“人员与任职”“标准与数据集”“治理”。

### 调整目标与区域顺序

| 区域 | 固定内容与顺序 | 动作位置 |
| --- | --- | --- |
| 侧栏顶部 | HDIP 工作区名 | 收起按钮在右端；键盘聚焦时可见 |
| 主导航 | 现有已实现条目按上述业务分组排列 | 当前条目用中性选中底；不使用醒目的大色块 |
| 规划内容 | 保留规划入口及其说明，降低视觉权重 | 分组可折叠；不把规划项伪装成可维护模块 |
| 侧栏底部 | 设计规范、主题、当前身份 | 开发期身份必须保留“开发期”标记 |
| 顶栏左侧 | 主题域→列表→当前对象 | 列表层为返回入口，当前对象名称可截断 |
| 顶栏右侧 | 全局查看日期及实际日期常驻可见 | 非今天时保留明显日期提示与“回到今天”；申请/配置页说明本页不按查看日期筛选 |
| 正文 | 页头→页面视图/工具栏→主体内容→计数/口径 | 页头、工具栏和数据区外沿按统一规范对齐；首列文字保留统一12px单元格内边距 |

采用页面感知的日期说明：对象目录、对象详情、人员/任职和组织总览继续使用查看日期；申请记录和配置字典页仍保留全局日期控件及当前值，同时明确显示“本页不按查看日期筛选”，不把它暗示为本页过滤器。跨页保留已选日期；申请内的每项业务生效日期仍独立显示。

**现有数据可做：** 统一水平起点、缩减重复边界、规划项分层、页面日期提示、分组折叠状态保留、主导航键盘反馈。

**接口依赖/后续研究：** 全局搜索、跨主题域待办汇总、收藏同步、角色工作首页。没有对应数据时不预先放“待我处理”“我的工作台”的空入口。身份切换不包装为已完成 SSO。

### 专项验收

- 导航仍为“人员与任职”，只含当前的人员名册与部门任职；不恢复已撤下的资质、临床授权、HR 岗位入口。
- `/changes` 徽标含义是当前可见的已提交申请数量，不显示为“我的待办”。
- 相同正文起点在列表、工具栏、标签页与详情中一致；宽台账不受文档模板的窄宽度重复限制。
- 1366/1440 CSS 像素桌面与窄屏均没有页面级水平溢出；日期控件不挤掉当前对象名。

## SC-02 变更申请列表

### 当前基线

路由：`/changes`。来源：[`pages/changes.tsx` L50–149](https://github.com/peterkis/hdip/blob/8c400c49757e2443ceeaa7e1358ba290c786e7c6/web/src/pages/changes.tsx#L50-L149)、[`ChangeRequestSummary`](https://github.com/peterkis/hdip/blob/8c400c49757e2443ceeaa7e1358ba290c786e7c6/web/src/api/generated/model/changeRequestSummary.ts)。

当前是状态胶囊和五列表格：编号、状态、变更内容、说明、最近处理；只有编号是详情链接。摘要接口只有 `id/status/note/item_labels/created_by` 及创建、提交、确认、退回、撤销时间。它没有对象摘要、生效日期、行级动作权限。最新服务端已对列表说明脱敏，不应重复报告旧问题。

### 调整目标

把它变成可快速识别一件变更的“清晰台账”。一期保留全部现有事实，不借视觉改造编造业务标题。

### 目标区域与行结构

1. 页头：“变更申请”及一句业务说明，说明记录不按全局查看日期筛选。列表不新增通用“新建申请”，仍从对象发起。
2. 单选状态标签页：全部、草稿、已提交、已确认、已退回、已撤销。状态写入 URL；不把已提交改称“待我确认”。一期没有全量统计契约时不显示六个未经核实的总数。
3. 双行工作列表，默认三列顺序为 **变更概要 / 状态 / 最近处理**；申请人位于概要第二行。
4. 底部显示本次返回的申请数量与当前状态；不混入业务对象数量。

| 行内位置 | 一期取值规则 | 文字角色 |
| --- | --- | --- |
| 概要第一行 | 有非空、可展示的 `note` 时使用其简洁预览；否则用现有变更类型与数量，例如“新建部门 ×3”；仍为空则“空草稿” | 工作项标题，清晰链接至详情 |
| 概要第二行 | `#编号`、`created_by.display_name`、变更项总数或类型概括；与第一行重复的部分省略 | 辅助信息；ID 等宽；不编造最近操作人 |
| 状态 | 当前申请状态文字与语义色 | 单个状态标签 |
| 最近处理 | 从现有时间戳确定的操作名称与时间 | 操作名正文、时间辅助；明确为记录时间 |

类型标签最多保留几个有区分价值的摘要，不把每个词都包成灰色胶囊。人写的说明只是说明，不能经前端解析后冒充结构化对象、生效日或系统判定。

**动作位置：** 主标题是稳定链接；鼠标 hover 和键盘 focus 明确显示进入详情。行尾可放一个“查看”次级入口，但不放直接确认、直接撤销或状态下拉。无需进入编辑模式也能复制编号。

**现有数据可做：** 行结构、文本层次、展示申请人、状态导航、已有字段的当前列表搜索、返回定位、无说明回退。若增加前端搜索，必须写“搜索当前列表”，搜索字段仅限已返回且允许展示的值。

**接口依赖：** 准确的“对象＋具体变更”摘要、多个生效日期的范围、问题数量、当前用户可执行动作、“我的待确认”、服务端搜索/分页/跨状态统计。需要服务端一次批量返回最小摘要并沿用脱敏；禁止每行请求详情补齐。

### 专项验收

- 有说明、无说明、已脱敏说明、空草稿、单类百项、多类申请均有不溢出的稳定行高和明确入口。
- 人写说明缺失时显示真实类型与数量，不出现虚构的科室名或申请主题。
- “已确认”行没有据此生成“今天已生效”；一期列表不添加不存在的生效日列。
- 一页有 N 行时不因此发出 N 次申请详情请求；申请人不再只藏在悬停文本中。
- 状态切换、进详情、返回后保留位置；移动端保留概要、状态、申请人和最近处理，不展示桌面空列。

## SC-03 变更申请详情与逐组核对

### 当前基线

路由：`/changes/:id`。来源：[`pages/changes.tsx` L152–375](https://github.com/peterkis/hdip/blob/8c400c49757e2443ceeaa7e1358ba290c786e7c6/web/src/pages/changes.tsx#L152-L375)、[`components/change-review.tsx`](https://github.com/peterkis/hdip/blob/8c400c49757e2443ceeaa7e1358ba290c786e7c6/web/src/components/change-review.tsx)。已有步骤条、按业务分组、字段前后对照、拆并图、问题定位、右侧核对导航、逐组“我已核对”门槛和后端权限。普通草稿不是任意拆项的编辑器；组织变更可返回原向导整体调整。

### 目标区域顺序

1. **页头**：变更申请编号＋状态；复制来源另列辅助说明。动作只按 `permissions` 展示。
2. **过程摘要**：起草、提交、确认的实际状态、操作人和时间；使用轻量步骤条，不占据一张厚重大卡片。
3. **阻塞信息**：校验问题、权限限制、脱敏说明。可处理的问题逐条保留并能跳到对应变更项。
4. **变更说明**：完整文本，独立于对象摘要。草稿可编辑时保留“保存说明”；提交时继续保存尚未保存的说明。
5. **主核对区＋侧边目录**：主区按现有业务分组展示；右侧目录显示组名、问题和核对进度。窄屏目录变为顶部可展开的组导航。
6. **结束区**：剩余核对数量、提交/确认的实际后果；长页面可提供“回到页头操作”锚点。提交/确认仍只有页头入口，不增加页底或悬浮的重复业务按钮。

### 分组内部格式

每组依次为组名与对象数、一个帮助判断的规则说明、业务对象行、展开后的前后对照、该组核对动作。对象名称优先；代码与来源申请为辅助。默认突出改动字段，允许查看全部字段。字段前后对照保留显式“变更前/变更后”标题，不只靠红绿识别。

拆分、分设、吸收合并、合并新设保留其不同身份结论；说明谁存续、谁退出、谁新设，以及关联对象的处理。图辅助理解，完整字段/明细仍可读。

**动作位置：** 页头右端为当前阶段主动作（“提交申请”或“确认申请”）；“回到向导调整”“复制为新草稿”为次级；退回/撤销按实际权限放次级或更多菜单。逐组核对按钮紧邻该组末尾。没有确认权的人能看见相应解释，不能因主按钮灰掉而无从知道原因。

**现有数据可做：** 分区、轻步骤条、对照密度、导航连续性、长页动作可达性和空/错状态。当前已有 `item_summaries/item_views/outcomes/problems/permissions`，可直接消费详情现有字段，不改确认事务。

**接口依赖：** 跨申请影响分析、自动风险评分、协同批注、未提供的审核责任人分派。不在本轮实现。

### 专项验收

- 未核对全部应核对分组时，任一提交/确认入口均不可绕过门槛；更新后的申请不能沿用旧核对勾选。
- 确认文案分开“正式登记完成”与“按每项业务日期适用”，未来开始的变更不被标成今天已适用。
- 退回必须填写现有必填原因；退回后的修改仍通过复制新草稿等既有方式进行。
- 隐去字段在标题、说明、对照、错误和复制预览中不重新泄露；完整明细不是靠 tooltip 才能阅读。

| SC-01 外壳 | 侧栏展开/收起、导航权限减少、非今天日期、规划入口 | 侧栏覆盖而不挤压正文；点导航后关闭；日期操作与面包屑不重叠 |
| SC-02 申请列表 | 空草稿、说明全/部分隐去、百项摘要、不同流程状态、请求失败 | 变更概要/状态在第一层，申请人/时间在第二层；名称链接与可选择文本均保留 |
| SC-03 核对详情 | 普通/组织变更、多组问题、无确认权、未核对完、未来生效、已退回 | 侧目录改顶部折叠；每个字段的变更前/后可上下排列但保留标签；长页动作不遮挡明细 |
| SC-04 部门列表 | 树被筛选截断、深层名称、未来节点、跨筛选选择、零正式履职 | 保留树缩进与展开控制，外层无横向溢出；对照列在表格内部滚动；批量条换行 |
| SC-05 部门详情 | 终态、无人员权限、无上级、多个别名、主/附加归属同时存在 | 属性区单列；七个标签横向滚动；关系图有对应明细可读，不要求用户缩放全文 |
| SC-06 单元列表 | 多个已选隐藏筛选、含下级、未来版本、暂停、父部门非正式履职 | 搜索全宽；活动条件回显；名称/类型/状态优先，其余列局部滚动 |
| SC-07 单元详情 | 无前后继、整体拆分/合并、已退出、历史日查询、无分类 | 关系属性单列；演变图必要时上下排，前身/后继文字与链接保持对应 |
| SC-08 主体 | 无有效版本、未来建立、多运营关系、许可证字段缺失 | 长信用代码可复制且不撑破页面；运营关系明细优先于缩得过小的图 |
| SC-09 院区 | 筹建/试运行/运行/停用、多个运营方、未知启用日期、长地址 | 多运营方换行；地址可展开；服务单元保持局部滚动与清晰上下文 |
| SC-10 总览 | 空筛选、无单元部门、零源代码、选中节点/连带/矩阵格、视图切换 | 桑基图切换到矩阵/明细入口；选择面板在下方；保留当前选中范围标题 |
| SC-11 编码台账 | 多解释、无候选、候选预选但未勾行、对象未建模、无配置权限 | 源代码/源名/来源明确；候选为可换行完整按钮；详情在单一弹层层级内切换 |
| SC-12 分类配置 | 大代码表、长判断文字、停用项、不可改代码、只读角色 | 方案块单列；说明自然换行；宽比较表局部滚动，不把判断文字缩成微字 |
| SC-13 人员名册 | 按日期/查重、无当前任用、计划任用、多任用子行、无导出权 | 姓名代码作为阅读起点；任用子行仍能对应部门/工号；查重模式说明常显 |
| SC-14 人员详情 | 有效/已结束/未来/已撤销任用，姓名更名/误录更正，敏感字段隐去 | 任用内部四类关系改纵向分区；每项动作仍靠近对应关系；不压成拥挤图标行 |
| SC-15 任职 | 负责人未登记、主持/代管、主部门不同、计划职务、历史依据缺失 | 共同范围置顶；负责人列表可折叠；台账范围说明与计数不断开 |
| SC-16 表单 | 缺必填、多字段错误、服务端拒绝、pending、未保存关闭、重复请求重试 | 标题/内容/底部动作分区；错误字段滚入视野；软键盘可见时仍可完成取消与保存 |

## 2. 交付范围与实施顺序

唯一阶段顺序以 [实施与验收](ui-implementation-plan.md) 的 U0–U4 为准，场景分组不另定义一套交付批次。

| 阶段 | 本文件对应范围 | 完成边界 |
| --- | --- | --- |
| U0 统一规范 | 全部场景的规则、索引与目标清单 | 先处理旧文档冲突和业务例外，不宣称运行时已迁移 |
| U1 申请列表试点 | SC-02及它必需的SC-01外框、连续行和状态导航 | 只用已有摘要字段；不同时改复杂核对或增加摘要接口 |
| U2 公共组件与列表推广 | SC-01、SC-04/06/08/09/11/12/13/15的列表区域 | 复用已验收规则，逐页处理筛选、密度、状态、导出口径与权限 |
| U3 详情、表单与复杂核对 | SC-03/05/07/14/16及SC-08/09详情；SC-10图形表达与明细连续性 | 保留现有确认门槛、身份与日期；处理前后对照、关系分组、焦点与返回位置 |
| U4 按证据推进增强 | 各场景标明的接口依赖和后续研究 | 摘要API、预览、保存视图等分别立项；没有必要性与契约不预先建设 |

人员相关调整沿用已完成的 A1 事实与权限；I1/R1后续能力按已有领域计划单独推进。本轮不同时加入看板、日历、甘特、通用布局编辑器或新增人员业务范围。
