# HDIP 统一 UI 视觉规范（Notion 风格）

2026-10-14 · 在线查看：应用内 `/design` · 令牌文件：`web/src/styles/tokens.css` · 依据：[notion-design-md.md](notion-design-md.md)

## 0. 操作动线与交互原则（优先于视觉）

前提：**操作动线必须符合人的操作直觉、路线合理**。维护人员熟悉的是对象的名称和业务事实，不熟悉系统内部的代码和规则。每个页面、表单提交前都要按下面几条检查。

1. **认名称，不记代码**。引用其他对象（院区、运营主体、部门……）一律从下拉框按名称选择，不让人手输代码。代码由所选对象带出，写进变更项（`components/forms/ref-selects.tsx`）。
   - 字段名要说清楚关系，例如“所属院区”“所属运营主体”，而不是“院区代码”。
   - 只有新建对象自身的“代码”需要录入，并放在名称之后。
2. **只给能选的**。下拉里不出现选了也会被拒的项：停用部门、停用院区不列出，“更换所属部门”不列出当前部门。同一张申请里新建的对象要出现在下拉中，并标“（本申请新建）”，这样“新建部门 + 改挂单元”可以一次完成。
3. **能推断的给默认值**。
   - 运营主体默认带出所选院区的主要运营方；只有一个主体时直接选中，并提示“已按所属院区带出，可改选”。
   - 生效日默认今天；从某个对象页面发起的操作，预先带好该对象。
4. **校验当场定位**。点“保存”后，所有缺漏或格式不对的字段**同时**按 Notion 风格标出（红边框、浅红底、下方一句说明），焦点落在第一个出错字段；改动某个字段后，它的标记立即消除。不要只弹一句“请填写××”让人自己去找。实现方式：表单 `build()` 用 `requireFields([...])` 返回字段级错误，字段用 `name` 对应（`components/forms/fields.tsx`）。
5. **从对象出发，结果回到申请**。在对象页面上发起操作（修订、重新绑定……），保存后跳到所在的变更申请，由那里提交、确认。一屏只有一个主按钮。
6. **后果先说清楚**。不可逆或影响面大的操作（永久退出、停用部门、拆分合并）要在弹窗说明里写明后果（如“代码永久绑定，不会释放”“已有单元保留引用”）。
7. **反馈与位置匹配**。成功和轻量结果用底部轻提示（toast）。需要照着改的问题留在原处：字段错误留在字段下方，申请校验未通过的原因留在申请页顶部。

## 1. 风格要点

- **安静的暖灰中性色，内容优先**。大面积只有白底、浅暖灰侧栏和黑色透明度文字；颜色只用来传达状态和主操作。
- **用透明度叠加表达层次**。文字、边框、悬停、选中都是黑（深色主题为白）的不同透明度，放在任何底色上都协调。
- **密度适中**。应用内正文 14px，控件高 28–32px，页面正文最宽 900px。
- **阴影极淡、圆角小**。标签 4、控件 6、卡片 8、弹窗 12；阴影多层叠加、几乎看不出边缘。
- **动效只做反馈**。悬停 100ms、弹层 200ms，缓动 ease。

依据文档提取自 notion.so 营销站。本规范保留它的色板、字号阶、圆角阶、阴影阶和动效时长（名称与值对应来源的 `--color-*`、`--font-size-*`、`--border-radius-*`、`--shadow-*`），并按 Notion 应用内的界面密度确定语义用法。

## 2. 令牌三层

| 层 | 命名 | 在哪 | 谁能用 |
| --- | --- | --- | --- |
| 原始令牌 | `--hd-<色系>-<级>`、`--hd-size-*`、`--hd-space-*`、`--hd-radius-*`、`--hd-shadow-*`、`--hd-duration-*` | tokens.css 第 1 段 | 只有语义令牌 |
| 语义令牌 | `--hd-text-*`、`--hd-surface-*`、`--hd-border-*`、`--hd-accent-*`、`--hd-danger/warning/success/info-*`、`--hd-tag-*`、`--hd-type-*`、`--hd-radius-<角色>`、`--hd-elevation-*`、布局尺寸 | tokens.css 第 2 段 | 页面、组件 |
| 桥接 | Tailwind 主题（`text-fg-muted`、`bg-surface-subtle`、`border-line`、`bg-brand`、`bg-tag-green-bg`、`text-xs`、`rounded-md`、`shadow-md`…）与 shadcn 变量（`--primary`、`--border`…） | `web/src/index.css` | 页面、组件 |

- 前缀统一 `--hd-`，避免与 Tailwind 自带的 `--color-gray-*` 冲突。
- 桥接层里没有任何色值或尺寸常量。

### 一键修改与替换

| 想做什么 | 改哪里 |
| --- | --- |
| 微调某个颜色在全站的值（如蓝色更深） | 原始令牌 `--hd-blue-600` |
| 改某种用途的颜色（如链接改用绿色） | 语义令牌 `--hd-accent-text: var(--hd-green-600)` |
| 换品牌强调色 | 语义令牌的 `--hd-accent*` 一组；或增加一个 `[data-accent="…"]` 块（已有 purple、teal 示例） |
| 深色主题 | `.dark` 块，只重定义语义令牌 |
| 整体字号放大一档 | `--hd-type-ui-size` 等文字角色令牌 |
| 换字体 | `--hd-font-sans` |

运行时切换：`lib/theme.ts` 的 `setTheme({ mode, accent })` 只在 `<html>` 上切换 `.dark` 与 `data-accent`，并记在浏览器本地。

## 3. 文字

| 角色 | 类 | 令牌 | 值 |
| --- | --- | --- | --- |
| 页面标题 | `text-xl font-bold` | `--hd-type-title-*` | 32 / 40，字距 −0.75px |
| 区块标题 | `text-lg font-semibold` | `--hd-type-heading-*` | 22 / 28 |
| 卡片、弹窗标题 | `text-sm font-semibold` | `--hd-type-subtitle-*` | 16 / 24 |
| 长段落 | `text-base` | `--hd-type-body-*` | 16 / 24 |
| 界面正文（默认） | `text-xs` | `--hd-type-ui-*` | 14 / 20 |
| 辅助说明 | `text-caption` | `--hd-type-caption-*` | 12 / 16 |

- Tailwind 的 `text-xs`～`text-xl` 已重定为上表角色。shadcn（base-mira）组件大量使用 `text-xs`，因此会随之变成 14px，不必逐个修改组件。
- 字体用系统字体，中文优先苹方、微软雅黑。不加载网络字体，以保证内网可用。字重只用 400、500、600、700。

## 4. 颜色用法

| 用途 | 类 |
| --- | --- |
| 标题、强调文字 | `text-fg-strong` |
| 正文 | `text-fg`（默认） |
| 说明、侧栏 | `text-fg-secondary` |
| 属性名、表头、提示 | `text-fg-muted` |
| 禁用、占位 | `text-fg-disabled` |
| 页面、侧栏、卡片、次级块底色 | `bg-surface-page`、`bg-surface-sidebar`、`bg-surface-raised`、`bg-surface-subtle` |
| 悬停、选中 | `hover:bg-surface-hover`、`bg-surface-selected` |
| 分隔线、输入框边框 | `border-line-subtle`、`border-line` |
| 主按钮、链接 | `bg-brand`（经 shadcn `Button` 默认样式）、`text-brand-text` |
| 提示块底色 | `bg-info-soft`、`bg-warning-soft`、`bg-danger-soft`、`bg-success-soft` |

## 5. 业务状态的标签色

状态一律用 `Tag`（`components/kit/tag.tsx`），颜色从 `lib/tones.ts` 取，保证同一状态在任何页面颜色一致。

| 业务 | 状态 → 颜色 |
| --- | --- |
| 院区运营状态 | 筹建 灰、试运行 蓝、运行 绿、停用 红 |
| 服务单元 | 在用 绿、暂停 黄、已退出 灰 |
| 部门生命周期 | 筹备 灰、正式履职 绿、暂停履职 黄、撤销 红、被替代 棕 |
| 部门管理主分类 | 维度不是状态，各类用不同颜色便于区分（`MAIN_CLASS_TONE`），不表示好坏 |
| 变更申请 | 草稿 灰、已提交 蓝、已确认 绿、已退回 橙、已撤销 灰 |
| 演变关系 | 拆分 紫、合并 粉 |

颜色的含义：绿表示在用或生效，黄表示暂停，红表示停用，灰表示未开始或已结束，蓝表示进行中。`Badge` 只用于计数和附注。

## 6. 组件

- **shadcn/ui（Base UI，base-mira）**：经桥接层自动套用令牌。只有 Badge、Button（xs）、NativeSelect（sm）三处原写死 10px 字号，已改为 `text-caption`。
- **合并类名**：`cn()`（`lib/utils.ts`）已登记自定义字号 `text-caption`。新增令牌字号时要同步登记，否则 tailwind-merge 会把它当成颜色类误删。
- **自建组件 `components/kit/`**：
  - `Tag`：Notion 彩色标签。
  - `Callout`：提示块，无边框、浅底色、左侧图标。
  - `PropertyList`：对象详情页顶部的属性列表。
  - `database`：列表页的数据库视图基本件，见第 8 节。
- **按钮**：一屏只放一个主按钮，其余用 `outline`、`ghost`。危险操作用 `destructive`（浅红底）。
- **表格**：采用 Notion 数据库式。无外框、只有横线分隔，表头为灰色常规字重，行悬停有底色。代码用等宽字体，状态用 Tag。

## 6.1 图标

- 统一用 `components/kit/icon.tsx` 的 `<Icon icon={…} />`，页面不直接使用两个图标库的组件。
- 选图标的顺序：先用 **hugeicons**（`@hugeicons/core-free-icons`）。它是 shadcn 与 ReUI 组件的 `iconLibrary` 配置，ReUI 的组件也用这套。没有合适的再用 **lucide-react**（例如“数据元”用的 `Blocks`）。
- `Icon` 统一尺寸（默认 16px，即 `size-4`）和线宽（1.75）。放在按钮文字前后时，用 `inline="start"` 或 `inline="end"`。

## 6.2 轻提示（toast）

- 用 react-hot-toast，样式全部取自令牌（`components/kit/toaster.tsx`）：浮起表面、细边框、弹层阴影、控件圆角、界面字号。显示在底部居中，深色主题自动跟随。
- 调用统一走 `lib/notify.ts`：`notify.success` / `notify.error` / `notify.info` / `notify.promise`。
- **用 toast**：成功、轻量的结果。例如已保存到草稿、申请已提交或已确认、已导出、已切换身份。
- **不用 toast**：需要用户逐条处理的校验错误，仍留在页面上（Callout 或表单提示）。toast 几秒后就消失，不适合承载要照着修改的内容。

## 7. 应用外壳（`components/layout.tsx`）

- **左侧栏**：宽 240（`--hd-sidebar-width`），底色 `bg-surface-sidebar`。
  - 导航按**业务主题域**分组，配置在 `components/shell/nav.ts`。新增主题域只需加一组数据，不改外壳代码。
  - 当前分组依次为：组织与关系（主体、部门、院区、服务单元）、空间与场所、人员、资质与任职（人员与身份、聘用与合作关系、岗位与任职、执业资质、临床授权）、标准与数据集（标准数据集、数据元、数据目录）、治理（变更申请）。
  - 尚未实现的条目标为 `planned`，显示为灰色，统一进入 `/planned/:key` 的“规划中”页面；没有条目的分组显示一行“规划中”。
  - 分组标题可以折叠。
  - 顶部是工作区名，悬停时出现收起按钮；窄屏（小于 768px）默认收起。
  - “变更申请”右侧的数字是待确认的申请数。
  - 底部依次是设计规范、深色/浅色切换、当前用户（开发期身份）。
  - 导航项高 28，悬停用叠加色，选中用 `bg-surface-selected`。
- **顶栏**：高 44（`--hd-topbar-height`）。
  - 左边是面包屑：一级取自导航项，详情页用 `useCrumb()` 补上对象名。
  - 右边是全局“查看日期”。不是今天时整块用黄色标签色高亮，并出现“回到今天”。
- **正文**：列表页最宽 1200（`--hd-page-wide-max-width`）。页头用 `PageHeader`：图标与 32px 粗体标题同一行，下面一句说明，右上角放操作。
- **详情页结构**（主体、院区、部门、服务单元、变更申请统一）：`PageHeader`（图标 + 名称 + 代码与版本说明 + 操作）→ `PropertyList`（属性名带图标，值旁用 `InlineAction` 放轻量操作）→ 若干 `Section`（`components/kit/section.tsx`：小标题 + 右侧操作）。不用卡片套卡片，不用 shadcn 的 Card / Alert / Table（提示用 Callout，表格用 database 组件）。
- **响应式（窄屏 < 640px）**：
  - 顶栏面包屑只留当前页面图标与当前对象名（截断），“查看日期”只显示图标与日期。
  - 列表工具栏的搜索框独占一行、占满宽度；筛选胶囊自动换行。
  - 详情页标签页横向滚动，不换行挤压。
  - 表格在自己的区域内横向滚动（`DbTable` 外层 `overflow-x-auto`），页面本身不出现横向滚动。
  - 关系图随容器宽度等比缩放并重新适配视图，容器高度按比例缩小（`components/flow-size.ts`）。
  - 验收：375px 宽度下逐页检查，没有元素超出视口。

## 8. 列表页 = Notion 数据库视图（`components/kit/database.tsx`）

- **工具栏**（`DbToolbar`）：
  - 左边放筛选胶囊 `FilterPill`。未选时显示“院区 ▾”；选中后变为强调色浅底，显示“院区：高新院区 ×”。
  - 开关胶囊 `ToggleChip`（如“含计划中”）也放左边。
  - 右边是搜索框 `SearchBox`，无边框，悬停或聚焦时显示底色。
- **筛选条件写在地址栏**（如 `?campus=8&type=IPD`），可以收藏和分享。
- **表格**（`DbTable` / `DbRow` / `DbCell`）：
  - 表头带图标、灰色、常规字重；列之间用细竖线，行之间用横线；行悬停有底色。
  - 第一列是名称，可点击进入详情。代码用等宽字体；状态用 Tag。
- **底部**（`DbFooter`）：显示计数和口径说明。
- **空状态**（`DbEmpty`）：一句说明和一个操作，不画插图。
- **页头操作**：“导出 CSV”用幽灵按钮，“新建”是主按钮。导出调用 `lib/download.ts`，按二进制保存以保留 BOM。
- **单元格内容不撑宽表格**：一格里可能有很多条目时（如申请的变更内容），合并同类并计数（“新建部门 ×94”），最多显示 3 类，其余收成“另 N 类”；长文本单行截断，悬停看全文；同类时间列合并为一列只显示最新一步。
- **批量操作**：可批量处理的列表在首列放勾选框，表格首行“全选当前列出的 N 条”（先用筛选缩小范围）；选中行用 `bg-surface-selected`。有选中时，底部出现贴底的操作条（`sticky bottom-3`，白底细边框阴影）：左侧“已选 N 条”，右侧“清除选择”与批量操作按钮。批量操作只生成一张多项草稿，弹窗标题写明数量，保存按钮写“生成 N 项”，跳过的条目在弹窗里说明。
- **层级树**：层级用连线表达——上级的竖线贯穿到最后一个下级，每个下级从竖线圆角转弯接到名称前（类似讨论区的回复引线）；有下级的行带展开 / 收起按钮，收起后显示“+N”。

## 8.1 图示与时间线

- **关系与演变图**（React Flow，`components/evolve-flow.tsx`、`components/operator-flow.tsx`）：只展示与点击跳转，不拖动、不缩放；节点是卡片（图标、名称、代码、一行说明、底部状态 Tag），背景点阵。
  - 共用件在 `components/flow-kit.tsx`：卡片节点 `FlowCard`、带标签的直角折线 `LabeledStepEdge`（**标签放在通往目标卡片的最后一段上**，多条线共用一段竖线时各自的状态不挤在中间）、自动适配 `AutoFit`。卡片标题 14px，副标题与底部（说明、日期、状态胶囊）一律 12px，胶囊高 20px。
  - 连线颜色用不透明的语义令牌 `--hd-flow-edge`（浅灰），多条线叠在同一段上颜色不加深；端点小黑点除外。
  - 运营关系图的连线标签：院区不在运行时写院区状态（筹建、试运行、停用），院区运行而关系尚未开始时写开始日，正在运行不加标签；多条线连到同一院区时标签上下错开。
  - 状态胶囊用低饱和度语义色：运行 = 浅绿，**计划中（筹建）= 浅黄**，试运行 = 浅蓝，停用 = 浅红，其他 = 白底细边框。卡片上的筹建状态写“计划中”，连线标签仍写“筹建”。
  - 主体—院区运营关系（细节按 ReUI Flow 区块）：连线为**直线 + 直角转折**（`step`），卡片有连线的一侧边中点有一个 6px 黑色实心端点（主体只在右侧、院区只在左侧；没有上级或下级的一侧不画）；查看日期当天**正在运行**的院区用灰色**流动虚线**（React Flow 自带 5px 虚线、0.5s 循环动画）；筹建、试运行、停用或关系尚未开始的，用**灰色实线 + 白底细边框标签胶囊**（标签落在竖段上）。卡片：左上图标框（主体为深色实心）、名称 + 代码、一行说明；底部分隔线下左侧小圆形图标 + 说明，右侧状态胶囊（运行 = 浅绿底绿字带勾，筹建 = 白底细边框带时钟，停用 = 浅红，试运行 = 浅蓝）。图下附图例。
  - 部门隶属与管理关系（`components/org-flow.tsx`，部门详情“隶属与管理关系”，列表保留在图下）：纵向是行政隶属——上级链在上、本部门居中（深色图标）、下级在下，实线；横向是管理关系——本部门管理 / 协作的对象在右，管理本部门的在左，虚线 + “关系：事项”标签；只画查看日期当天有效的。
  - 拆分、合并、部门沿革：左列前身，中间节点写类型与生效日，右列后继；退出 / 新设 / 存续用不同 Tag。
