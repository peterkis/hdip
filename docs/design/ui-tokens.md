## 0. 使用方式与适用边界

本规范为项目视觉与交互的唯一规范入口。它保留 HDIP 已有的中文、业务语义、组件体系和可维护性，吸收 Gr8r 的统一对齐、连续行、主辅分区和信息层级。规则适用于组合后的整页体验，也适用于单个组件。

### R-GOV 规范优先级

1. 用户已经明确的业务决定、领域设计与接口契约决定身份、日期、权限、业务状态与写入后果。
2. 本文件决定视觉角色、组合规则、交互表达和验收目标。规范中的“必须”是实现要求，“建议”允许以真实场景证据调整。
3. ui-scenarios.md 规定场景中的字段顺序、动作位置、响应式行为和数据前提；它引用本文件的通用尺度。
4. tokens.css 是运行时令牌来源；index.css 负责桥接。实现尚未迁移的部分不能被当成本版已完成。
5. notion-design-md.md 保留为历史参考材料，其营销站字号、外链字体与抽取异常不得直接指导应用开发。Gr8r 源码作为设计方法参照，不整体移植。

本版的关键决定要同步到应用内 /design。若改变接口或业务规则，继续遵守 CLAUDE.md 的同步与生成流程；纯视觉调整不触发数据库迁移。

### R-GOV 业务范围与写入路径

- 业务对象的新增、修订、关系调整与分类赋值，沿用变更申请流程。保存草稿、提交申请、确认申请是不同动作。
- 分类方案及代码、来源系统及字典等既有配置维护，保留后端已授权的直接保存路径；按钮写“保存配置”。不得把“所有写入都经申请”写成没有例外的全站提示。
- 当前人员模块是身份、任用、归属与部门任职的共享目录。UI 调整不扩张为 HR 岗位、资质证照、临床授权或账号权限系统。
- 名单导入暂停与 I1 来源人员键对应是不同事项；视觉改造不能以“完善页面”为由启动它们。
- 保留主体、院区、部门、服务单元的独立身份。名称近似、同属院区或同一服务单元，不构成自动合并或迁移依据。
- 组织总览的统计与图形继续使用既有口径；新增展示方式不得引入第二套统计结果。

## 1. 视觉目标与页面组合

### R-VIS 01 内容优先

首屏应让用户辨认三个要素：正在维护什么对象或集合、当前观察范围、可以采取的下一步。标题与名称承担主体；状态与变化承担判断；代码、来源和时间承担核对。

不得用增加彩色卡片、装饰插图、渐变、阴影或动画代替信息组织。允许独立工作台模块使用一个轻边界容器；容器中的记录继续使用连续行。

### R-VIS 02 整页只有三种空间关系

| 空间关系 | 用法 | 间距规则 |
| --- | --- | --- |
| 同一字段或同一条记录内部 | 名称与代码、图标与文字、标题与元信息 | 4 或 8px |
| 同一任务的相邻区域 | 页头与视图导航、工具栏与数据区、组标题与行 | 12 或 16px |
| 不同任务或不同信息组 | 属性区与关系区、关系区与历史区 | 24 或 32px |

同一列表的行之间 gap 为 0；行自身通过内边距提供呼吸空间。不能同时叠加“父容器大 padding、子卡片大 padding、单元格大 padding”。

### R-VIS 03 页面主辅结构

- 工作列表：页头 → 状态或视图导航 → 搜索及筛选 → 已选条件 → 连续行 → 计数与口径。
- 对象详情：页头 → 核心属性 → 关系或下属对象 → 历史。优先复用 PageHeader、PropertyList、Section。
- 申请核对：页头主操作 → 处理步骤 → 问题清单 → 说明 → 业务分组核对 → 结束提醒；核对导航在满足宽度时放右侧。
- 概览：标题与范围 → 共用概况条 → 主图或主清单 → 点选结果与口径。已有六项概况继续使用六项，不为仿照参考图强行改成四项。
- 日常工作台只在具备真实待办和权限口径后建设。左侧主任务、右侧辅助时间或活动信息可使用约 3:2 的比例；该比例不应用于所有页面。

## 2. R-LAY 页面外框与响应式

### 2.1 页面外框

| 参数 | 本版目标 | 应用说明 |
| --- | --- | --- |
| 展开侧栏 | 240px | 沿用现有变量；窄屏为覆盖层 |
| 桌面顶栏 | 44px | 紧凑定位与查看日期；窄屏内容可增高，不能裁切 |
| 标准水平 gutter | 24px | 视口宽度 ≥768 CSS px |
| 窄屏水平 gutter | 16px | 视口宽度 <768 CSS px |
| work 内容最大宽度 | 1440px | 列表、台账、申请核对；数值指内容净宽 |
| document 内容最大宽度 | 900px | 长文字详情或简单对象文档；数值指内容净宽 |
| canvas 内容最大宽度 | 不设额外上限 | 组织总览、关系图与矩阵等经场景明确使用 |
| 页头距顶栏下缘 | 24px | 窄屏 20px |
| 页面底部余量 | 48px | 有贴底操作条时还须预留操作条实际高度及安全间距 |

设侧栏后可用宽度为 W，gutter 为 G，页面类型上限为 M，则净内容宽度为 min(W−2G, M)；canvas 的 M 视为无限。超宽屏将整个内容外框居中。禁止把“最大宽度”一处解释成含 padding、一处解释成净宽。

每页只能选择一个外框策略。顶栏面包屑内容槽、页头、视图栏、筛选栏、表格外沿应引用同一策略。工作区切换、收起按钮等属于外壳控制，不能引起正文各模块逐层缩进。这里对齐的是内容槽左边缘；有固定图标或树缩进的文本不要求全部文字落在同一像素。

当前基线中顶栏 px-3、正文桌面 64px、申请内层 900px 属于待迁移事实。新规则先在申请列表试点；其他路由保持已有布局，迁移到同一外框时才移除旧的重复 padding。

### 2.2 不同页面的宽度选择

| 页面 | 外框 |
| --- | --- |
| 部门、院区、主体、服务单元、人员、任职、编码映射、分类方案列表 | work |
| 变更申请列表及复杂申请详情 | work |
| 简单对象属性及长文字依据 | document；有关系图/台账的完整详情可用 work |
| 组织总览及需要充分横向空间的图表 | canvas |
| /design | work |

页面模式由路由或页面元数据显式指定。优先扩展现有 Layout/PageHeader；不建设可任意拖拽的布局编辑器。工作页面不能在外层 work 中再无说明地套 900px 容器。

### 2.3 侧栏与顶栏

- 侧栏按现有业务主题域分组，名称来自 nav.ts。当前“人员与任职”仅保留人员名册与部门任职，不恢复过时的资质、授权菜单。
- 导航行目标最小高度 32px，16px 图标，图文间距 8px；计数不与名称竞争。选中状态同时提供底色及文字/位置线索。
- 侧栏折叠控制可被键盘聚焦；不能仅在鼠标悬停时才可发现。
- 顶栏的全局“查看日期”必须常驻可辨认。非今天显示浅黄提示与“回到今天”，同时显示实际日期。
- 院区筛选不得伪装成账号或工作区切换。是否改变权限、查询范围与创建默认值须按既有业务分别处理。
- 申请计数仅表达现有查询口径。缺少当前用户待办权限依据时，不改名为“我的待办”。**项目决定（2026-10-24 Peter）**：变更申请的“待我确认”按服务端 `approval_rule` 判断（`waiting_for_me`），有权限依据，侧栏角标 = 待我确认数。

### 2.4 响应式行为

| 条件 | 行为 |
| --- | --- |
| ≥1280 CSS px | 正常桌面布局；是否显示右侧核对导航还需检查内容净宽 |
| 768–1279 CSS px | 优先保留名称、状态和主要动作；辅助列可收进详情；搜索与筛选允许两行 |
| <768 CSS px | 侧栏默认收起；gutter 16px；单列页面；触控主要操作最小 44px 高 |
| <640 CSS px | 面包屑缩为当前页面/对象；搜索占满一行；筛选自动换行；详情标签页允许横向滚动 |
| 320/375 CSS px | 页面主体不得横向滚动；必要的二维表格在自身容器滚动，并保持明确滚动边界 |

核对页的右侧目录在净内容宽度至少 1040px 时采用 200px 侧栏和 24px 间距；更窄时移到分组内容上方。主内容应保持可读宽度，不以隐藏核对进度换取空间。

不要将宽表随意变成“每格一个字段”的重复长卡片。窄屏先确定主字段、保留比较所需的二维结构，再决定列隐藏或局部横向滚动。任何隐藏列必须有可访问的详情入口。

## 3. R-TYP 中文排版与信息主次

### 3.1 字体与字号角色

继续使用现有系统字体链，不依赖外网字体；中文采用设备上的苹方、微软雅黑等。Geist 只是参考项目的英文选择，不作为 HDIP 必须新增的字体依赖。

| 角色 | 字号/行高 | 字重 | 使用范围 |
| --- | --- | --- | --- |
| 工作页标题 | 24/32px | 600 | 列表、台账、申请列表、总览 |
| 文档页标题 | 32/40px | 600或700 | 对象文档首页，长名称可自然换行 |
| 页面内章节标题 | 16/24px | 600 | 关系、历史、业务分组标题 |
| 行主标题/对象名 | 14/20px | 500或600 | 连续行、表格名称、变更主语 |
| 界面正文 | 14/20px | 400 | 字段值、按钮、表格、说明短句 |
| 长段落 | 16/24px | 400 | 需要持续阅读的依据或说明正文 |
| 辅助说明/元信息 | 12/16px | 400 | 代码、时间、数量、字段辅助说明 |
| 图上非关键角标 | 11/14px | 500 | 现有层级角标；不得承载唯一状态、错误或操作说明 |

现有 text-xs =14px 的桥接必须保留。工作标题另设语义角色，不将现有 text-xl 全局改成 24px。新增 Tailwind 字号别名时同步 cn()/tailwind-merge 分类，防止字号与颜色类相互覆盖。

中文 UI 字距默认 0。文档标题取消源于英文营销标题的负字距，避免汉字紧挤。代码采用现有等宽字体；姓名、部门名及中文标签不使用等宽字体。

### 3.2 行内阅读顺序

同一记录的主次为：

1. 名称或具体变化：深色、必要时中等字重。
2. 状态或动作含义：文本明确，按既有业务色使用一个主要状态标记。
3. 所属关系与范围：说明其属于哪个部门、院区、主体或来源字典。
4. 编号、代码、操作人、时间：位置稳定、字号较小、对比度仍满足可读性。

申请核对中的主语、谓语、宾语继续有不同形态：主语为无底色的名称；谓语为这一行唯一的实底着色动作标签；宾语为细边框引用标签。多种颜色不能把整个句子拆成一排同等强度的标签。

### 3.3 中文、英文、代码和数字的组合

- 中文句子用中文标点。界面标签不通过人工插空格对齐，如不得写“姓  名”；应由布局控制宽度。
- 自然语言中的英文缩写、数字与中文可留一个半角空格，例如“导出 CSV”“已选 12 条”。保存的名称、正式代码、工号、源系统值必须原样保留，不能为排版改写数据。
- 数字列右对齐，数量采用等宽数字特性；代码列左对齐。不要用居中对齐弥补列宽设计。
- 人名、机构名、业务短语不使用英文式 Title Case，也不强制全大写；代码大小写沿用接口约定。
- 持续阅读的中文说明左对齐，不使用两端分散对齐。短字段标签不因字数不同而拉开汉字间距。
- 对标题和正文使用正常中文换行规则；避免“，。；：）】”被单独挤到行首。长 URL/无空格编码可在自己的单元格内部折行，不向全局文本套用 word-break: break-all。
- 数据中的空值、零、未登记、不可查看和加载中分别显示；它们不能都变成一个横线。

W3C 中文排版需求作为中文标点和混排的研究依据；具体字号、行高与间距是本项目的 UI 选择，不能表述为 W3C 规定。[中文排版需求](https://www.w3.org/TR/clreq/)

### 3.4 截断与完整查看

| 内容 | 默认 | 完整查看方式 |
| --- | --- | --- |
| 单行台账对象名 | 一行，列宽不足可截断 | 名称链接进入详情；键盘聚焦可查看说明 |
| 双行工作列表主摘要 | 最多两行 | 标题链接；详情显示完整内容 |
| 说明、依据、校验问题 | 按内容换行 | 不截断用户需要照着修改的句子 |
| 代码、工号 | 优先完整显示 | 若确需截断，提供可访问的完整值及复制入口 |
| 来源名称/字典名称 | 可截断 | 详情或可聚焦的信息提示 |
| 状态与动作按钮文字 | 不截断 | 调整布局或换行操作区 |

仅依赖 HTML title 的悬停信息不算完整查看方案。提示内容沿用后端已脱敏结果；不能在 tooltip、复制文本、ARIA 标签或隐藏 DOM 中暴露被遮蔽的值。

## 4. R-COL 色彩、边界与主题

### 4.1 中性色与强调色

保留 HDIP 现有的白色主体、暖灰侧栏和品牌蓝。参考 Gr8r 的轻重分配，不引入第二套 --bg/--text 变量。

| 角色 | 基线来源与本版决定 |
| --- | --- |
| 页面/内容表面 | 保留 --hd-surface-page / raised，浅色为白 |
| 侧栏 | 保留 --hd-surface-sidebar，浅色取现有暖灰 |
| 次级块 | 保留 --hd-surface-subtle，仅用于表头、只读区、轻提示等 |
| 主文字/正文 | 保留 strong/primary 语义层级 |
| 可读元信息 | secondary 优先；muted 只在实际底色对比通过时使用 |
| 悬停/选中 | 现有透明度叠加；选中必须区别于 hover |
| 分隔线 | subtle；仅辅助分组，不承担唯一可交互边界 |
| 重要输入/焦点边界 | 单独验收非文本对比；不能因追求轻淡而看不清 |
| 主强调 | 默认品牌蓝；紫/青主题仍需分别通过状态矩阵验证 |

页面与组件只引用语义令牌或桥接类。禁止为了达到截图颜色，在页面局部写十六进制色值或替换一整套原始色板。

### 4.2 业务颜色裁决

项目既有业务映射继续以 lib/tones.ts 为来源：

| 语义 | 视觉 |
| --- | --- |
| 计划、筹建、筹备 | 浅黄底标签，加明确文字 |
| 运行、在用、有效任用、已确认 | 绿标签，文案保留各自含义 |
| 暂停 | 橙标签 |
| 停用、撤销等当前已定义为红的生命周期终止 | 低强度红标签；不自动增加整行红底 |
| 已结束、已退出、已撤销申请等已定义灰的状态 | 中性灰标签 |
| 已提交、试运行等当前定义 | 沿用蓝及对应明确文字 |
| 被替代、拆分、合并 | 沿用既有棕/紫/粉含义，不复用为审批状态 |

附件中“停用改灰”的通用建议不纳入本版，原因是项目已明确“停用红、结束灰”。保留业务辨识，同时降低大面积色块的强度。申请“已确认”不能通过绿色被描述成所有未来业务变化已经开始生效。

同一个状态的标签跨页面保持一致；状态标签、分类标识和统计图分类色是三套不同用途。图表可以为相邻类别可区分而使用不同色值，但必须保持稳定映射、可见图例和文字含义。不要把分类色解释为好坏或风险等级。

编码治理“待裁决”明确保留当前两个作用域：台账标签使用 `CODE_STATUS_TONE.pending = yellow`，统计图使用 `CODE_BREAKDOWN_TONE.pending = orange`。两者均写“待裁决”，图表提供图例，含义是等待人工判断。“计划浅黄”是计划状态的业务约定，不表示所有黄色标签都是计划或暂停。

### 4.3 主按钮颜色状态目标

现有 Button 存在以透明度实现主色 hover 的路径，本版要求改为明确的语义状态色。下表是目标值，均复用现有原始色板；不是已经修改的运行时结果。

| 主题/强调色 | 默认背景 | hover 背景 | pressed 背景 | 前景 |
| --- | --- | --- | --- | --- |
| 浅色/蓝 | blue-600 | blue-700 | blue-800 | white |
| 浅色/紫 | purple-600 | purple-700 | purple-800 | white |
| 浅色/青 | teal-600 | teal-700 | teal-800 | white |
| 深色/蓝 | blue-300 | blue-200 | blue-400 | gray-900 |
| 深色/紫 | purple-300 | purple-200 | purple-400 | gray-900 |
| 深色/青 | teal-300 | teal-200 | teal-400 | gray-900 |

按基线原始色值进行 sRGB 计算，以上 18 组前景/背景均达到普通文字 4.5:1；浅色蓝默认约 4.57:1，是余量最小的一组。最终仍应在真实组件的透明度、边界、遮罩与状态组合下验证。深色链接/焦点强调使用相应浅色阶，不被浅色 data-accent 规则覆盖。

明确声明 .dark 与 data-accent 的组合语义；不能只修默认蓝，留下紫/青组合覆盖错误。disabled 可以采用禁用样式，但不得降低 loading 状态下仍需阅读的文字。

### 4.4 边界、圆角、阴影

- 标签 4px、控件 6px、模块容器 8px、弹层 12px，沿用现有语义角色。
- 连续行不单独带外圈圆角或投影；整组需要容器时只画一层边界。
- 数据表默认只有横向细分隔线；对照表或确需逐列比较的矩阵可显式启用竖线。
- 弹层与悬浮操作条使用现有轻投影；静态列表不悬浮。
- 选中、焦点、错误三种状态不能只靠同一种边框深浅区分。

## 5. R-ROW 连续行与表格

### 5.1 三类记录布局

| 类型 | 目标尺寸 | 内容 | 边界 |
| --- | --- | --- | --- |
| 标准数据行 | 最小 44px | 名称及属性列，适合比较 | 行间细线，无行卡片间隙 |
| 紧凑数据行 | 最小 36px | 明确选择紧凑密度后的熟练维护 | 字号仍14px，保留点击目标 |
| 双行工作列表 | 最小 64px | 主要说明 + 元信息，用于变更申请 | 同一容器连续排列，名称优先 |
| 对照行 | 内容决定，最小44px | 字段/变更前/变更后 | 可有竖向比较线 |

这些高度均为最小值，不裁切换行内容。双行行的一个可验收组合为：上/下内边距各12px、主行20px、行间4px、元信息16px，共64px。标题占两行时自然增高。

表头目标36px，14px常规字重；表头文字必须可读。标准单元格水平内边距12px；上下间距由行类型统一控制。表格外沿与上方工具栏对齐，首列文字可以保留一个统一的12px单元格内边距。

### 5.2 申请工作列表的默认结构

| 区域 | 内容与角色 |
| --- | --- |
| 弹性主列 | 第一行安全说明/摘要；第二行申请编号、申请人、变更项数或类型概括 |
| 状态列 | 一个明确的状态标签 |
| 最近处理列 | 动作名与时间；完整时间可访问 |
| 可选末列 | 仅显示已有权限支持的轻操作；首期不虚构确认快捷按钮 |

主列应至少获得可用宽度的一半；中文标题不足约16个汉字的阅读宽度时，将元信息降到第二行或收起次要列。窄屏可将状态放到主行末端、处理时间放入元信息行。

第一期不要求返回不存在的 subject/effective_date/permissions。优先使用 API 已返回且已脱敏的 note；为空或只含遮蔽提示时，以 item_labels 生成中性、确定性的类型摘要。不要从说明自由文本猜测身份、日期或可执行动作。

**项目决定（2026-10-24 Peter，U1 定稿）**：采用本节的三列双行版式，第一行改用服务端的确定性摘要 `headline`（“对象 · 变化”，与详情的一句话说明同源、同规则脱敏，名称一次查出、不逐行取详情——即 U4“业务摘要”的前提已满足）；第二行为编号 · 申请人 · 项数与类型构成 · 退回原因 · 说明；最近处理写真实处理人与相对时间（见 R-DAT 8.1）。导航为“全部 / 待我确认 / 我的草稿 | 草稿 / 已提交 / 已确认 / 已退回 / 已撤销”。

类型标签不能与状态、名称一起形成多排同等强度彩色标签；类型通常使用文字或中性辅助标记，最多展示三类并准确说明“另 N 类”。

### 5.3 点击、选择与展开

- 名称或主摘要必须是真实链接，支持 Enter、浏览器新标签页和复制链接。
- 行背景点击可作为额外便捷入口，但不能用可点击 tr 代替可聚焦的名称链接。
- 复选框仅用于已支持的批量操作；与状态标记、展开箭头有不同形态和可访问名称。
- 行内链接、复选框、菜单、复制按钮不能触发外层行导航。
- 焦点可见；hover 不是唯一可发现操作的方法。对触控和键盘始终保留明确入口。
- 不在名称链接上嵌套其他按钮，也不把编辑表单的焦点当成跳转命令。
- 普通列表不新增自动拖动排序、看板拖动改状态或点击勾选确认生效。

### 5.4 列与分组

- 主体名称列可伸缩；状态、日期、代码等列有一致的角色宽度，不能靠任意固定宽度挤压名字。
- 默认列仅服务当前任务；长依据、完整历史、全部映射放详情。
- 分组由业务维度决定，标题显示组名、数量与必要口径。分组间24px，组内连续行。
- 同一组的子标题、行名称起点和数量位置保持稳定。树缩进使用每级20px，连接线辅助阅读，不以颜色或空格模拟层级。
- 宽表可保留冻结名称列；使用时需验证横向滚动下底色、边界与焦点不重叠。

### C-02 页头

标题下只放当前页面最有用的一句范围说明。规则长文移到就近说明或帮助区。右侧一个主按钮，其余 outline/ghost；无写权限时不提供假按钮。已有申请核对页仍只在页头保留提交/确认主操作，不在页底重复。

“一个主动作”以当前任务上下文为单位：页面、模态表单各有自己的主动作；打开模态表单后，其“保存到申请”或“保存配置”是当前上下文的主动作，页面背景不再参与交互。分区或行内动作使用次级表现，不与页级主动作竞争。申请核对页的单一页头入口仍按上述特殊约束执行。

### C-03 单选导航

“全部/草稿/已提交/已确认/已退回/已撤销”是互斥状态筛选，使用单选分段按钮组或正确的标签页模式。若只改变同一集合的筛选，优先原生 button + 当前选中语义；若采用 ARIA tabs，则必须完整实现 tablist、tabpanel、选中态和方向键行为。

数量只有在已取得对应完整口径时显示。当前筛选结果的数量不能冒充全站各状态总数。状态导航与“含计划中”这类独立开关分开。

### C-04 搜索与筛选

常用条件直接可见；更多条件可进入弹层，但生效后仍显示条件标签。单项清除与清空全部不清除用户不相关的查看日期或页面状态。输入搜索时保留焦点，查询节奏与网络策略统一，避免每个页面自己实现一套 debounce。

筛选、排序、查看日期和受支持的视图写入现有 URL 状态机制。参数名必须与接口相符；没有导出支持的筛选不能悄悄忽略。切换范围时清理或明确提示已选记录，不能保留不可见选择后直接批量提交。**项目决定（2026-10-25，U3R-02，部门列表 SC-04）**：同一查看日期内，搜索、筛选和表 / 树切换保留所选对象（存勾选时查询返回的行，不只存 id）；选择条显示“已选 N 个，其中当前列出 M 个”，可展开完整名单逐条取消，可清除没列出的；选择条、名单与批量表单用同一个集合。查看日期或身份改变即清空并提示一次，渲染上不出现“新日期 + 旧选择”。批量表单写明“选择 N 个、跳过 K 个（原因）、生成 M 项”。

### C-06 属性与引用

桌面属性标签建议占128px，值列自适应；窄屏上下排列。**项目决定（2026-10-25，U3）**：有外框的页面里属性名不画装饰图标（128px 正好放下 8 个汉字，如“统一社会信用代码”），属性行不加悬停底色（属性不可点）；属性旁的轻量操作是 28px 按钮，用负边距不撑高属性行。字段名说明关系，如“所属部门”“运营主体”，不能简化成含糊的“部门代码”。对象引用显示名称；代码在名称后辅助，不要求用户记码。引用标签使用现有 ref 形态；图标表达对象类型，不新增大面积对象底色。

### C-08 控件尺寸

常规按钮、输入和选择器目标32px；行内小操作28px；视觉图标16px，其独立点击区域至少24×24px，通常采用28或32px。触控主要按钮和表单控件目标44px。对多行说明、错误信息和文本域采用内容驱动高度。

必须核实 Button、Input、NativeSelect、DateInput、搜索、分页或行内动作的实际 CSS。仅修改 --hd-control-height 不算完成。避免将 loading 状态当 disabled 而降低关键文本可读性。

### C-11 侧边预览的后续契约

有连续核对需求再实施。建议宽度 min(560px, 100vw−32px)，不足768px使用完整页或全宽预览。普通预览只读，顶部显示对象类型、名称、代码与“完整查看”，支持 Esc、关闭回焦、浏览器返回语义及直接链接。

每次只为当前选中对象加载详情；快速切换取消或忽略过期请求。不能预先为列表全部行请求详情。若存在未保存表单，按现有表单离开规则处理，不静默丢弃。

## 7. R-ACT 表单、动作和反馈

### 7.1 按钮文案对应真实后果

| 情况 | 按钮文案 |
| --- | --- |
| 业务表单写入申请 | 保存到申请 |
| 既有草稿提交 | 提交申请 |
| 有权限且已核对的确认 | 确认申请 |
| 配置/字典维护 | 保存配置 |
| 批量业务动作 | 生成 N 项变更 |
| 返回核对完整页面 | 查看详情或进入核对 |
| 终态申请再次发起 | 复制为新草稿 |

“确认申请”后根据实际业务生效日反馈。允许使用既有“确认生效”文案的页面应同步解释日期口径；优先迁移为不混淆处理状态和业务时间的“确认申请”。

### 7.2 表单顺序

名称/对象 → 关键关系 → 期间 → 其他属性 → 依据/说明。代码与拼音码就近放置但主次分明。

- 院区、部门、服务单元及人员院内代码由系统分配，保存前写明“保存时由系统分配”，不得显示为可编辑必填字段。
- 主体代码保留当前人工录入规则。外部字典正式代码及人员业务工号不等同于 HDIP 自动代码。
- 已选对象自动携带其代码，引用选择器展示名称；同申请新建对象有明确标记。
- 默认值必须有业务依据。因对象或关系开始日期推后生效日时，显示原因，不能仅写“已自动填充”。
- 日期统一使用现有 DateInput；保持 YYYY-MM-DD，不根据操作系统区域改成日/月顺序。

### 7.3 校验与恢复

提交时一次展示可识别的全部字段错误，将焦点移到第一处；顶部摘要可链接到字段。用户修改后重新校验该字段；只有通过的错误才清除。不得沿用“键入任意字符就清除错误”的旧描述。**项目决定（2026-10-25，U3）**：变更表单外壳 `ItemDialog` 在标红后每次改动都调用表单自己的 `build()` 重新检查，只保留仍不通过的字段，不给未标红的字段新加错误；有输入时关闭先确认一次。

请求失败保留输入并说明能否重试；双击不能生成重复申请或重复代码预留。已有幂等键与预留规则保持原样。

**公共表单契约（2026-10-25，U3R-01）**：

- **纯校验与提交定位分开**：表单的 `build()` 只按当前值返回结果——变更项（或数组）、`FieldErrors`、字符串整体提示（不保存，如“没有修改任何内容”“已有相近人员”）、空数组（不保存）；不得在里面 setState、切换面板、发请求或预留代码（外壳每次渲染都可能调用它重查）。点“保存到申请”未通过时要切到出错面板（如拆分的后继），写在 `ItemDialog` 的 `reveal(errors)` 里，外壳随后把焦点放到第一个标红字段；之后改字段时的重查不切面板、不移焦点、不滚动。
- **重查**：字段错误只清掉已通过的、不给未标红的字段新加错误；整体提示在 `build()` 重新给出变更项时才消失，仍是字符串时换成最新说法；服务端拒绝留到下一次保存。
- **改动保护**：原生输入框、下拉、复选框由外壳监听；不产生原生事件的编辑（标签 ×、退格删标签、选项胶囊、增删后继 / 前身、“按名称重新生成”）经 `kit/form-edit` 的 `markDirty()` 报告——`ToggleChip`、`TagInput`、`TextField` / `SelectField`、`EditButton`（表单里的行内“移除”）、拆分合并图的“再加一个”已接入。纯浏览（切换查看哪个后继、展开说明、只打开日历）不算改动。采用“本次打开期间改过即算”的保守策略：改回原值仍会问一次。取消、×、Esc、点遮罩都走同一入口，改过时只问一次“继续填写 / 放弃并关闭”；继续填写把焦点放回原字段（原字段已不在时放到第一个输入框），放弃后焦点回到打开表单的按钮。
- **按钮类型**：表单内的原生 `<button>` 除“保存到申请”外一律写 `type="button"`；`components/ui/button`（Base UI）默认就是 `type="button"`。
- **保存中与失败**：提交处理器自身防重入（不只靠按钮禁用），保存中不关闭（关掉也撤不回已发出的请求）、取消与目标草稿停用、字段区整组停用；失败后输入、结构、所选后继、目标草稿与请求键都保留，提示“保存未成功：……已填写的内容都还在”，重试复用同一请求键、拿回同一批代码。请求键只用于代码预留，草稿写入接口本身不是幂等的；不自动重放结果不明的请求。组织变更向导（`reorg-wizard.tsx`）尚未接入本契约，留 U3R-04。

对于复杂申请，错误展示依次说明：发生了什么、哪些对象/日期有关、怎样修改；跳转到对应项后给短暂定位反馈。成功用现有 notify；需要持续修正的问题留在页面。

### 7.4 变更详情的特殊约束

- 按后端 `item_views`、`item_summaries`、`problems`、`problem_message`、`outcomes`、`permissions` 等已有数据组织内容；不能靠颜色猜测操作结论。
- 保留逐组“我已核对”。它是阅读进度，不能替代权限判断、服务器预演和确认事务。
- 不新增逐项删除，防止拆散组织变更的整体申请；继续使用已支持的“回到向导调整”或复制草稿路径。
- 不恢复已移除的“这张申请做什么”大卡片。页面标题及现有说明已承担该职责。
- 不在列表加入点勾确认、不用拖拽改变申请或对象状态。
- 核对进度随申请内容版本保持有效；任何导致内容变化的路径都须沿用已有重置/校验逻辑，不把旧阅读状态用于新内容。

## 8. R-DAT 日期、权限与数据表达

### 8.1 三类日期必须分开

| 类型 | 表达 | 规则 |
| --- | --- | --- |
| 查看日期 | 查看日期：YYYY-MM-DD | 决定读取视角，明确显示 |
| 业务期间 | YYYY-MM-DD 至 YYYY-MM-DD；空结束日为长期有效 | 闭区间，两端均含当日 |
| 审计处理时间 | YYYY-MM-DD HH:mm；详情可到秒 | 沿用接口本地无偏移时间，不做时区转换 |

修订在 D 生效时，旧版到 D−1、新版从 D 起；UI 日期对照必须反映此关系。不要将“申请确认日期”当作对象变更开始日期。未来版本和计划中关系仍需文字说明。

相对时间只能作辅助。重要业务日期、到期判断与审计核对必须能直接获得绝对日期。**项目决定（2026-10-24 Peter）**：工作列表里的处理时间写一目了然的相对说法——今天 / 昨天 带时:分，更早的写“N天前 / N周前 / N个月前 / N年前”（`lib/format.ts` 的 `relStamp`）；精确时间在详情页的处理步骤里，列表上悬停也能看到。业务日期不用相对说法。“未登记负责人”不等于实际岗位空缺，“未登记单元”不等于医院没有开展该业务。

### 8.2 权限与真实能力

- 后端决定可见数据与可执行动作；前端只表达结果。
- 现有列表缺少对象摘要、有效期与动作权限时，用现有字段降级；不能把详情的字段当成列表已有字段。
- 不根据申请状态独自推导“轮到我处理”；不根据申请人姓名猜测当前用户权限。
- 脱敏内容在列表、详情、悬停、复制、导出与可访问名称中保持一致。
- 人员无权限状态应区别于空名册；不能显示“共0人”暗示结果为空。
- 新增摘要或全局搜索须复用已有可见性与脱敏边界，避免在搜索候选中泄露对象存在性或敏感内容。

### 8.3 数字与计数

计数说明它数的是对象、变更项、源记录还是任职记录。加载显示骨架或“—”，完成后真实0才显示0。过滤后的数量、全库数量和当前分页数量不得混用。

“覆盖率”“完成度”“未映射率”等比例只有分子、分母、时点和去重规则明确时才展示；不得为了复制参考图的进度条生成主观完成度。

## 9. R-STATE 状态、空态和错误

| 状态 | 表现与操作 |
| --- | --- |
| 首次加载 | 保持区域高度的轻骨架；有可访问的加载文本 |
| 筛选中/刷新中 | 保留已有结果并标明更新中；不把旧结果包装成当前口径 |
| 真实空数据 | 一句说明；有权限时给与上下文一致的创建入口 |
| 筛选无结果 | 说明当前条件无匹配；提供清除相关筛选 |
| 未登记 | 明确写“未登记”或项目既定文案，不推断不存在 |
| 无权限 | 明确权限状态及可行返回路径，不用空表掩盖 |
| 请求失败 | 保留范围和输入；显示重试及必要错误说明 |
| 部分失败 | 按实际业务契约表达；申请确认仍保持整张事务语义 |
| 操作成功 | 说明保存的是草稿、配置或确认结果；重取受影响查询 |
| 数据冲突/校验失败 | 就地显示，定位相关字段或记录，保留用户上下文 |
| 未保存离开 | 遵守现有表单挂载/关闭规则；有用户输入时给必要的明确离开后果 |
| 规划中 | 保留既有规划页，不伪造可用列表或完成百分比 |

错误颜色不能覆盖全部正文。Callout/ProblemCard 采用浅底、小图标、清楚标题与修正方法，不使用粗红色侧条制造整屏视觉压力。

## 10. 图、矩阵、时间线与动效

### R-GRAPH 图形语义

保留现有关系图与统计图的不同用途：

- 主体—院区运营关系：运行中的流动虚线属于项目已确认的语义；其他状态采用既有实线及标签。计划状态统一浅黄，删除旧文档同一筹建状态白底/浅黄冲突。
- 行政隶属与管理关系：分别用原有纵向实线和横向虚线表达，不把演变关系画成上下级。
- 桑基图：维持稳定输入排序与不播动画；一张图只用颜色表达一个维度。
- 矩阵：名称列与数量/类型关系清楚，格子为空写未登记含义。统计来源与对应清单保持同一筛选结果。
- 关系图保留可点击对象及图下可读信息；绘图装饰不能截获对象链接。
- 在减少动效模式中，运营虚线停止流动，并通过文字或图例继续表达“运行中”。

边标签默认保留 `LabeledStepEdge` 的目标侧末段规则：横向进入目标时锚定目标侧横段中点，纵向进入时锚定目标侧竖段中点；同一目标的多条标签沿用 `stack/stackOf` 的22px序号错位。不得统一强制放在共用竖段。本轮不更换图布局算法；窄屏改用可读明细时仍保留关系名称。

图形常量继续以现有共用图形组件 `flow-kit.tsx` 及相应业务图组件为依据，页面口径见 ui-scenarios.md。没有本次实际业务需求的汇报模式、图片导出或图形编辑不纳入视觉试点。

### R-MOTION 动效

hover 100ms，普通弹层/状态过渡200ms。新增、更新或错误定位可以有一次性轻反馈；不添加逐行延迟进场、数字滚动、庆祝动画。

动画不能造成布局跳动、延迟按钮可用或掩盖请求失败。prefers-reduced-motion 下移除位移、呼吸、流动及计数动画。图表和长列表优先保持稳定。

## 11. R-A11Y 可访问与实际环境验收

- 正常文字按实际前景与背景达到至少4.5:1；本版所有14px及12px信息都按正常文字检查。不要把24px工作标题的例外阈值误套给正文。
- 理解控件所需的边界、图标和状态至少3:1；纯装饰分隔线不承担这一职责。控件不能只靠极淡线条表明可操作。
- 独立指针目标至少24×24 CSS px，规则允许的行内文本等例外需有明确依据；本项目桌面常规控件32px、触控主要控件44px为项目目标。
- 所有主要流程可用键盘完成；焦点清楚且不被贴底工具条、固定顶栏遮住。
- 筛选按钮、图标按钮、复选框、日期选择器有可访问名称；表头排序状态放在相应列头语义上。
- 模态弹窗管理焦点、Esc 与关闭回焦；非模态预览不套用与实际行为不符的 aria-modal。
- 页面在320 CSS px和200%文字/浏览器缩放场景下可读；确需二维比较的表格在自身范围滚动。
- 颜色、悬停、动画均不能是唯一信息渠道。
- 切换主题与强调色后分别检查正文、标签、主按钮、输入边界、焦点与图表；不以色板截图代替组件状态验证。

依据：[WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。本规范引用验收目标，不声称当前应用已经通过 WCAG 认证。

实际环境至少覆盖1366、1440、1920桌面与768、375/320窄屏。Windows显示缩放100%/125%须在实际环境单独记录；CSS视口、物理分辨率、浏览器缩放、设备像素比不能混为一项。

## 13. 完成标准与证据

一个页面迁移完成，应同时满足：

1. 已选择外框模式，页头/工具栏/数据区对齐，核心内容没有被重复padding挤压。
2. 中文主次可辨，名称完整查看可达，重要状态和日期直接可读。
3. 现有数据足以支撑所有展示与动作，没有用推测填补接口缺失。
4. 键盘、窄屏、深色和强调色状态通过本轮有范围的检查。
5. 一条代表性维护任务能顺利完成并返回原上下文。
6. 文档、/design示例与实际组件行为一致；验证记录区分已执行与未执行。

完整的分阶段任务、命令和验收记录格式见 ui-implementation-plan.md。先完成申请列表试点，再推广公共组件，避免一次性全站替换造成业务核对回归。
