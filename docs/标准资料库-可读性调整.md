# 标准资料库：来源资料层与标准定义层的用户呈现调整

日期：2026-11-04。范围：只改页面呈现，外加一个只读筛选参数；不改数据库、不重导资料、不升读取器、不改引用解析规则与既有网址。

起因：Peter 看了标准列表和 GB 11714—1997 详情后提出两点。一是列表看不出资料属于哪一类；二是“各来源写法”把 Drive、uniData、JSON 位置、文件摘要直接铺在概览上，使用人员看不懂。参考了外部评估（`HDIP_两层用户呈现调整评估.md`，不入库）并结合仓库核对后，定下以下做法。

## 1. 原则

- 默认页面只回答四件事：这是什么、标准状态怎样、现在能看什么、有没有影响理解的差异。
- 加工证据（来源对照、原记录、摘要、读取器版本、复核状态原值）放在一直可达的“整理记录”。一条不删，只是不在默认页面铺开。
- “自动化整理”只描述处理方式，不等于官方状态已核实、内容已复核，也不等于医院已采用。只写有记录支持的事实。

## 2. 资料类别

| 类别 | 依据 | 说明 |
| --- | --- | --- |
| 国家标准 | 系列 GB、GB/T | 与强制 / 推荐性质分开：第一列写类别，类别下写“强制性 / 推荐性”（按当前登记的标准号前缀，不推断现时适用效力） |
| 行业标准 | 系列 WS、WS/T | 同上 |
| 参考资料 | `reference_material` | 第一列写“参考资料 + 细类”（统计报表 / 官方参考资料 / 医保更新）；没有标准状态 |

- 筛选：`GET /api/standards/editions?category=national|industry`，在计数和分页前筛选。页面“类别”筛选的选项依次是国家标准、国家标准 · 强制性（GB）、国家标准 · 推荐性（GB/T）、行业标准……，后几项写入旧的 `series=`，旧网址照常可用。
- “标准 | 参考资料”两个列表不合并。以后需要“全部资料”时另设统一只读查询，在服务端统一筛选、计数、分页，不拼两个接口的第一页。
- 国际标准、院内规范、地方 / 团体标准：没有资料前不加类别，也不加没有内容的筛选项。迁移 0025 只允许 GB、GB/T、WS、WS/T，真要接入时，编号形式、发布主体、院内发布状态另行设计。外文文件不自动归为国际标准，本地 PDF 也不自动归为院内规范。

## 3. 取得渠道与“自动化整理”

- 页面上的渠道分两类：官网目录快照、官网下载是**官方来源**；其余（Drive 归档清单、Drive 归档 01～99、uniData 历史目录与补源）写**本院归档资料**。默认页面不逐个区分 Drive、mdm、uniData。
- 官网不并进“自动化整理”：官方目录是权威入口，并进去以后，“有官方依据”和“只有归档资料”就分不出来了。
- 数据库里的 `source`、`raw`、摘要、记录位置都不改。来源声明的身份包含来源，批量改名会改变身份；原来源名在整理记录里照录。
- 同一文件出现在多个归档里，不算多份独立证据。

## 4. 标准详情

页签：**概览 | 原文与附件 | 结构化内容（有才显示） | 整理记录（一直显示）**。旧的 `?tab=records` 仍指向整理记录。

- **概览 · 基本信息**：类别、标准号、性质、标准状态、发布日期、实施日期；废止日期只在已废止或有值时出现；在线阅读只在有地址时出现。
- **概览 · 需要注意**（只在有差异时出现）：
  - 已登记的目录—文件差异（`difference` / `file_identity`，连同整理说明）；
  - 官方目录记载的名称 / 实施日期与当前目录不同；当前值来自人工更正时写明更正编号。

  归档资料的写法不同（大多是按文件名记的标题，开发库 333 处）不当作告警，只在摘要下方计数。
- **概览 · 收录与整理**：
  - 整理方式：自动化整理；
  - 官方目录：已列入，或“本库未登记这项标准的官方目录记录”；
  - 状态依据：有依据写依据；没有写“尚未登记能核实这项标准状态的权威依据”，不写“没有官方来源”；
  - 原文：份数、取得渠道、阅读入口，并注明“入库时已按文件摘要核对，与登记的文件一致；这不说明内容已逐字复核”；
  - 结构化内容：有则给条目数，没有写“本库暂未展示”，不断言没有被解析过；
  - 人工更正：只写更正了哪个字段，不说“整份标准已人工审核”；
  - 整理说明。
- **原文与附件**：显示标题按角色写（正文 / 修改单…，同角色多份时编号），动作是“阅读 / 查看”；文件名、摘要、来源、身份核对、整理备注收进“文件信息”。空状态写“本库暂未收录原文”，维护操作说明不放在使用页面上。
- **整理记录**：目录维护信息（官网写法、官网分类、核实日期与依据、差异类别、文件内标识、整理说明）、各来源写法（第一行是渠道，其次是原来源名，原文链接写“打开原文”，不再重复“当前目录”一行）、人工更正、结构化处理修订、登记历史。

## 5. 标准定义层（数据元、值域、代码）

- 正文不变：名称、DE / CV 编号、定义、数据类型、表示格式、允许值、数据元版本、章节、码值都按原值显示。允许值旁的定位结果和“名称不一致 · 待核对”保持原位，引用四项规则不改。
- 页头只在历史处理修订时写“历史处理修订（读取器 vN）”，更新提示照旧。当前处理修订不在页头写读取器版本。
- **出处**：PDF 物理页与“查看原文第 N 页”、印刷页码、表内位置、所据原文、资料记载的问题。问题列表为空时写“原资料未登记问题”，并说明这不表示已复核无误。
- **整理记录**（可折叠）：处理修订、包内成员、记录位置、源记录 ID、资料复核状态与导入标记（原值）、原单元格、原件与图证、索引出处、原始记录。复核状态与导入标记这一批不做中文对照：取值含义需要逐项确认，避免被读成“已通过”。
