# 人员共享数据契约

2026-10-24 · A0，A1 更新 · 依据：`docs/人员域边界复审与实施计划.md`。本文只写**现在代码里实际提供的**人员数据及其口径；以后每增加一个共享输出（A1 的部门任职台账、I1 的来源人员键对应……），在这里补一节。

## 1. 本轮消费者

**模拟消费者，尚未对接真实系统。** 现有接口与导出只在走查库里用合成人员验证过；还没有 HIS、HR、OA 等系统按这些接口取数。已确认的近期真实用途（2026-10-24 Peter）：

| 用途 | 对应阶段 | 状态 |
| --- | --- | --- |
| HIS / HR 等系统按平台人员代码对人 | I1 来源人员键对应 | 未开始：待定第一个来源系统、人员键字段与“永不复用”的确认人 |
| 高新院区开诊后的院区人员派驻 | R1 院区服务角色 | 未开始：待定派驻信息的维护方、角色码表、试运行日期 |

真实人员数据进入前，须先完成服务端身份认证（S0）；现在的 `X-HDIP-User` 是开发期身份，不能证明请求者是谁。

## 2. 事实与责任

`recorded_by`、`confirmed_by` 回答“谁在平台上录入 / 确认了数据”，**不**回答“谁作了人事或医务决定”。

| 事实 | 业务决定与来源维护 | 平台做什么 | 平台不做什么 |
| --- | --- | --- | --- |
| 人员身份、姓名历史 | 组织人事部（人员管理责任方） | 分配人员代码（`P` + 6 位，永不复用）、登记姓名及更名 / 更正 | 按姓名或工号自动合并人员 |
| 任用、业务工号 | 组织人事部；合作、进修、规培、实习由相应归口部门 | 登记已决定的关系、类型、期间与工号 | 招聘、入离职审批、劳动合同 |
| 主 / 附加部门归属 | 组织人事部 | 登记行政归属与期间 | 推断实际工作院区 |
| 部门任职（部长、副部长、主持工作、代管） | 有权任命方 | 登记已形成的任职结果及其依据（任命、交接必填，文字，不做附件、不校验文号） | 任命决策、干部考核；职务不是系统权限 |
| 来源人员键（I1，未实施） | 来源系统的维护方 | 人工核实后登记对应 | 写回来源系统 |

## 3. 现有输出与粒度

所有人员接口都需要“查看人员”权限（`person.view`），导出另需“导出人员数据”（`person.export`）；服务端检查，没有权限返回 403。敏感字段按 `PERSON_FIELD_PERMISSIONS` 置空并列入 `masked_fields`（目前没有登记任何敏感字段；工号不敏感）。

| 输出 | 一行 / 一条是 | 日期与筛选 | 要注意 |
| --- | --- | --- | --- |
| `GET /api/persons` | **一个人**（按人员去重） | `as_of`（默认今天）；`q`、`status`、`institution_id`、`department_id`、`include_future`；`scope=all` 为查重，不看日期 | 每人下的任用摘要里，“部门”是该任用在查看日期的**主部门**（`PRIMARY`），附加归属不出现；`department_id` 筛的也是主部门 |
| `GET /api/persons/{id}` | 一个人的全部历史 | `as_of` 只决定“当前姓名、当前状态” | 各数组含全部期间的记录，**不是**都在查看日有效；按 `valid_from / valid_to` 判断，`void = true`（生效前已撤销）的不算 |
| `GET /api/departments/{id}/persons` | 该部门的**一条部门归属**（主归属与附加归属都有，看 `kind`） | `as_of`；`include_future` | 不含下级部门；一人在同部门同时有主归属与附加归属不会出现（规则禁止）；人数请按 `person_id` 去重 |
| `GET /api/departments/{id}/duties` | 该部门的**一条职务** | `as_of`；`include_future` | 代管者可以不归属该部门；负责人 = 当天的主持工作者（有则优先），否则正式部长 |
| `GET /api/person-duties`（A1，页面“部门任职”） | `rows`：**一条职务**，附任职部门、此人当天的**主部门**（计划中的职务取开始日；代管时两者不同）、任用、依据、登记申请；`leaders`：一个部门当天的部长职务（空 = 空缺） | `as_of`；`q`（人员或任职部门名称）、`department_id`（任职部门，不含下级）、`duty`、`mode`、`include_future` | `record_count` / `person_count` 只算当天有效的（一人兼两职记 2 条、算 1 人），计划中的另计 `planned_count`；`leaders` 只受部门筛选影响，列出当天正式履职的部门及当天有部长职务的部门；依据为空 = A1 之前登记，显示“历史记录未提供依据” |
| `persons.csv` | 一个人：`person_code, name, pinyin, relation_status, relation_status_name` | `as_of` + 名册的筛选：`q`、`status`、`department_id`、`include_future` | 与名册页面同一批人（A1）；名册的“全部人员”查重视图不按日期，不能导出 |
| `person-relations.csv` | 名册里每人的一项任用，附当天主归属（计划中的任用取最早计划） | 同 `persons.csv` | 暂未分配时部门列为空（不是离职）；附加归属不出现；末尾 `not_yet_effective`（A1 追加）。列名与列顺序是对外契约，新增列只加在末尾 |
| `person-duties.csv`（A1） | 一条职务，列同台账：任职部门、职务与方式、人员、任用、主部门、期间、`not_yet_effective`、`basis_note`、`change_id` | 与台账同日期、同筛选 | 依据为空 = A1 之前登记 |

人员数据集接受的筛选登记在 `services/export.py` 的 `PERSON_DATASETS`；传了数据集不支持的筛选返回 422，不会悄悄导出全量。

CSV 为 UTF-8 带 BOM；工号按字符串原样输出（`0007`），用 Excel 打开时请以“文本”导入，否则可能丢前导零。

## 4. 日期口径

| 日期 | 含义 |
| --- | --- |
| 查看日期 `as_of` | 业务日期：这一天谁在任用、归属哪里、担任什么职务 |
| `valid_from / valid_to` | 业务期间，闭区间，起止都含当日；`valid_to` 为空 = 尚未登记结束日 |
| `recorded_at`、申请的 `submitted_at / confirmed_at` | 平台记录时间，与业务日期无关 |
| 来源截至日期 | 目前没有（未接来源系统）；I1 起由来源对应的“观察日期”表达 |

## 5. 未知与缺失怎么显示

| 情况 | 显示 | 不能理解为 |
| --- | --- | --- |
| 任用有效但当天没有主归属 | “暂未分配”，部门列为空 | 离职 |
| 当天没有有效任用 | 状态“无效任用”（有计划时为“计划中”） | 在所有机构都离职；本平台只记录试点主体 |
| 任用结束 | “本次任用关系已结束” | 其他系统的离院处置已完成、资格注销 |
| 没有资质 / 授权数据 | 不显示（本平台不采集） | 无资质、无权限 |
| 部门没有登记职务 | 负责人“空缺” | 院方确认无负责人 |
| 职务没有依据 | “历史记录未提供依据”（A1 之前登记） | 任命无效、没有任命文件 |
| 任用延长后职务仍止于原日期 | 职务按原结束日结束 | 已免职：职务不随任用延长，续任须另行登记（A1） |

## 6. 已知限制

- 试点单主体；同一人员同一主体的任用不并行（放开需同时改数据库、应用、页面与测试，本期不放开）。
- 工号只在同一主体内唯一，不是跨系统人员主键；跨系统对人等 I1。
- 申请页的敏感字段已按同一登记表隐去（2026-10-24，`services/masking.py`）：结构化内容置空，文字里的值替换为“（已隐去）”，响应带 `masked_fields`。
