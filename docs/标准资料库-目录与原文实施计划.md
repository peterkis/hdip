# 标准资料库：标准目录与原文实施计划

依据：建设计划（`docs/标准资料库-建设计划.md`）第 4、6 节；F0 / F1 开发计划、F2 开发计划；Peter 2026-10-31 对标准资料页的意见。

**状态：草案（2026-10-31），待 Peter 确认第 9 节的决定后开发。** 本计划插在 F2 第一批与 F2 后续批次、F3 之间。F0–F2 的成果全部保留，不重新导入，也不升级读取器。

## 1 为什么要先补这一层

Peter 的判断：“以权威原始资料及其发布信息为依据，以标准目录为管理入口；在其上关联原文文件、结构化定义和来源关系。PDF 是当前最主要的原文载体，但不是唯一的来源形式。”

现在的页面难读，原因在 F1 的建模，不只是少了几列：

| 现状 | 后果 |
| --- | --- |
| 列表一行是一个 `source_document`，也就是“某个资料包经读取器 vN 处理出的一份结果” | 页面上的单位是处理修订，不是标准。同一标准有 v1、v2 两行，资料包、读取器、覆盖数挤在第一屏 |
| `source_document.title` 有列，但导入命令从未写入（2026-10-31 确认） | 标准没有名称，只能靠编号辨认 |
| 只有被解析过的标准才有行 | 363.1、364.1、364.2 这类没有结构化成果的分册在库里不存在，看不出“缺什么” |
| 发布、实施、废止日期与标准状态都没有登记 | 无法回答“这项标准现在还有效吗” |
| 原 PDF 只是 `source_pdf` 里的一段路径文字 | 打不开原文，也就做不到从定义回到原文 |

可以直接利用的条件：31 份 v2 处理修订（和 2 份 v1）都记录了原 PDF 的 SHA-256（`source_document.source_sha256`），6684 条条目的出处里有 `source_sha256` 与 PDF 物理页。Peter 手上的原 PDF 只要摘要一致，就能确定是同一份文件，**不需要重新解析**。

## 2 范围

**做：**
- 标准目录：一项标准一行（按“标准号 + 年份”），登记名称、发布机构、发布 / 实施 / 废止日期、状态及核实依据。目录信息有历史，不覆盖。
- 原文文件：登记本地持有的原件（正式文本、勘误、发布公告、附件、阅读副本），记录大小与摘要，可在浏览器里打开。
- 已有结构化成果按规则挂到目录与原文上，读取时计算，不改 `source_document`。
- 页面以标准为入口：目录列表 → 标准详情（概览 | 原文与附件 | 结构化内容 | 来源与处理记录）；数据元、值域页面显示所属标准，可“查看本条出处”跳到原文页。
- 第一批登记 WS/T 363—2023 与 WS/T 364—2023 全部 34 个分册。

**不做：**
- 不重新导入、不升级读取器、不改 `source_document` / `standard_entry` / `standard_reference` 的结构与已有行。条目 ID 与已有链接不变。
- 不解析 PDF 内容（不抽文字、不数页数、不做 OCR），不自建 PDF 阅读器。
- 不做目录的页面编辑、上传页面、Drive 同步、定时抓取官网。
- 不做关系图谱视图、图数据库；不做院内采用、发布与消费（建设计划第 1.1 节）。
- 院内文件本批不登记（模型支持，见第 9 节 D3）。
- 不收补查包里的其他标准、历史版、364.5 文件 A（`标准资料库-值域引用补查.md` 第 3 节）；它们以后按各自来源另批登记目录。

## 3 对象与表（一次迁移，0025）

三张表，都由 `hdip_owner` 创建，`hdip_app` 只有 SELECT；只由本地导入命令用迁移账号写入，与标准资料库其他表相同（CLAUDE.md“例外：标准资料库”）。

### 3.1 `standard_edition` 标准（身份）

一行 = 一项标准的一个版次，如 “WS/T 363.3—2023”。只留身份，登记后不可改。

| 列 | 说明 |
| --- | --- |
| `id` | 永不复用 |
| `standard_no` | 标准号，写法与 `source_document.standard_no` 相同（`WS/T 363.3`）；去首尾空白、非空 |
| `standard_year` | 四位年份文字 |
| `registered_at` | `LOCALTIMESTAMP` |

约束：`UNIQUE (standard_no, standard_year)`；全行受 `hdip_guard_update()` 保护。

院内文件没有标准号（第 9 节 D3），以后收入时再定身份写法，本批不预留列。

### 3.2 `standard_edition_version` 标准的目录信息（只追加）

沿用 HDIP“身份 + 版本”的写法：目录信息每改一次追加一行，最新一行即当前信息，旧行保留。这里的“版本”是目录记录的修订，**没有业务有效期**，不用 `valid_from / valid_to`。

| 列 | 说明 |
| --- | --- |
| `edition_id` | → `standard_edition` |
| `seq` | 该标准的第几次登记，从 1 起；`UNIQUE (edition_id, seq)` |
| `title` | 中文名称，按正式文本封面原样 |
| `title_en` | 英文名称，选填 |
| `category` | `NATIONAL` 国家标准 / `INDUSTRY` 行业标准 / `LOCAL` 地方标准 / `GROUP` 团体标准；`option_item` 给中文名 |
| `publisher` | 发布机构，原样文字（如“国家卫生健康委员会”） |
| `issued_on` / `effective_on` | 发布日期 / 实施日期，选填 |
| `status` | 记录的官方状态：`CURRENT` 现行 / `ABOLISHED` 废止；**空 = 待核实** |
| `abolished_on` | 废止日期；按通告原样登记（“自 2024-04-01 废止”就写 2024-04-01），不套用组织版本“新版开始前一天”的写法 |
| `replaces` / `replaced_by` | 代替关系，按原文写法的文字数组（如 `["WS 363.1—2011"]`）；读取时在目录里查找，找不到就只显示文字，不建占位标准 |
| `verified_on` | 状态与日期的核实日期；`status` 非空时必填 |
| `basis_url` / `basis_note` | 核实依据：官方详情页或公告地址，及说明（如“国卫通〔2023〕×号”）；`status` 非空时两者至少一项 |
| `change_note` | 本次登记改了什么，导入命令按差异生成（“首次登记”“改实施日期”） |
| `recorded_at` | `LOCALTIMESTAMP` |

检查约束：`status = 'ABOLISHED'` ⇔ `abolished_on` 非空；`effective_on >= issued_on`（两者都有时）。全行受保护。

**状态的口径：**
- 库里只记依据官方来源核实到的状态。没有核实的一律“待核实”，**不能因为没填废止日期就当作现行**，也不按下载文件名里的“现行”判断。
- “即将实施”不存，读取时推算：`status = CURRENT` 且 `effective_on` 晚于今天。
- “已被代替”由 `replaced_by` 表达，状态仍按官方写法记录。
- 页面同时显示核实日期，如“现行 · 核实于 2026-10-31”。核实日期较早时不另提示，由人判断。

### 3.3 `standard_file` 原文文件

一行 = 本地持有的一个文件。同一标准可以有多份（364.5 的文件 A / B 就是同一标准的两份正式文本）。

| 列 | 说明 |
| --- | --- |
| `id` | 页面与接口只用 id，不暴露服务器路径 |
| `edition_id` | → `standard_edition` |
| `role` | `OFFICIAL_TEXT` 正式文本（来源可追到官方） / `OTHER_COPY` 其他副本（字节不同、来源未闭合的原件，见第 10.1 节） / `ERRATA` 勘误与修改单 / `ANNOUNCEMENT` 发布公告 / `ATTACHMENT` 附件 / `PAGE_IMAGE` 原页图（官方只给页图时，如 WS 218—2002） / `READING_COPY` 阅读副本（OCR、压缩件） |
| `stored_path` | 相对 `HDIP_STANDARDS_DIR` 的路径，须在 `originals/` 下 |
| `original_name` | 下载时的原文件名 |
| `media_type` | 以 `application/pdf` 为主；官方原格式是 Word 或页图时照收（GB/T 4754—2017 的 DOCX 正文与修改单、WS 218—2002 的 GIF 页图） |
| `bytes` / `sha256` | 登记时计算；`sha256` 64 位小写十六进制 |
| `source_page_url` / `download_url` | 官方详情页 / 直接下载地址，选填 |
| `obtained_on` | 取得日期 |
| `note` | 如“与国家卫健委公告附件逐字节相同”“Drive 另存，官方下载链未闭合” |
| `registered_at` | `LOCALTIMESTAMP` |

约束：`UNIQUE (edition_id, sha256)`（同一文件不在同一标准下登记两次）；`UNIQUE (stored_path)`；`bytes > 0`；全行受保护。同一个文件挂到两项标准（合订本）允许，各登记一行。文件登记错了不改不删：在 CSV 里标 `withdrawn`，导入命令追加一行撤回说明——这一需要等真的遇到再加，本批不建。

### 3.4 已有成果怎样挂上（读取时计算，不建表）

挂接是确定的，没有需要人裁决的情形，所以不建挂接表：

| 挂接 | 规则 |
| --- | --- |
| 处理修订 → 标准 | `source_document` 的 `standard_no + standard_year` 与 `standard_edition` 完全相同 |
| 处理修订 → 原文文件 | `source_document.source_sha256` 与该标准下某个 `standard_file.sha256` 相同 |
| 条目 → 原文页 | 条目所在处理修订挂上了文件，且条目出处有 `pdf_pages`，跳到第一个物理页 |

- 只按摘要认同一份文件。**A 文件的页码不拿到 B 文件里跳**，即使标准号、年份都相同（如 364.5 文件 A / B）。
- 处理修订找不到标准时，页面说“目录未登记该标准”；找到标准、但没有摘要相同的文件时，说“未登记本条所据的原文（摘要 `xxxx…`）”，并列出该标准已登记的其他文件（不带页码）。
- 以后若遇到标准号写法不同、要人工指定的情形，再加挂接表。

## 4 目录怎样维护：仓库里的 CSV + 导入命令

| 文件 | 内容 | 入库 |
| --- | --- | --- |
| `data/standards/editions.csv` | 一项标准一行，列同 3.2（`replaces` 等数组用 `;` 分隔） | 是 |
| `data/standards/files.csv` | 一个文件一行，列同 3.3，含 `sha256`、`bytes` | 是 |
| `hdip-standards/originals/` | 原件；按系列、标准号与年份分目录（`<系列>/<系列>-<编号>_<年份>/`，如 `WS-T/WS-T-363.3_2023/`），**保留原文件名，不改名、不覆盖** | 否（`.gitignore`） |
| `hdip-standards/reading-copies/` | OCR、压缩等另存的阅读副本，和原件分开 | 否 |

- 名称、日期、状态都是公开信息，数据量小，放进 Git：谁在哪天按什么依据改了哪项，提交记录就是审计线索，不用另做审批或编辑页面。
- `files.csv` 里的 `sha256` 是“预期摘要”：Git 记住是哪一份文件，导入时本地文件必须与它一致。

命令 `api/scripts/import_catalog.py`（迁移账号）：
- `--fill`：只为 `files.csv` 里 `sha256` 为空的行计算大小与摘要并写回 CSV，不碰数据库。
- `--check`：读两份 CSV 与本地文件，打印将要新增的标准、追加的目录版本、登记的文件，以及全部问题，不写库。
- 不带参数：在一个事务里写入；任何一行有问题就整体回滚，报“文件:行号 列名：原因”。
- 规则：
  - 新标准 → 身份 + 第 1 版；已有标准的目录字段变了 → 追加一版；没变 → 不写。重复执行不增行。
  - CSV 里删掉了已登记的标准或文件 → 拒绝（库里不删）。
  - 文件：路径须在 `originals/` 或 `reading-copies/` 下、存在、大小与摘要和 CSV 一致；已登记的文件信息变了 → 拒绝（本批不支持改）。
  - 日期 `YYYY-MM-DD`；`status` 非空时须有 `verified_on` 与依据。
  - 只读本地文件、不执行、不解压；PDF 只算摘要，不解析。

## 5 原文的读取

- `GET /api/standards/files/{id}/content`，权限 `standard.view`（第 9 节 D4）。按 id 找到 `stored_path`，解析后必须仍在 `HDIP_STANDARDS_DIR` 下；比对大小（不每次重算摘要，建设计划第 6.1 节），不一致或文件不在时返回 404 并说明“原文文件不在资料目录 / 已变动”。响应 `Content-Type: application/pdf`、`Content-Disposition: inline`（带原文件名）。
- 现在的开发期身份放在请求头 `X-HDIP-User`，浏览器直接打开链接带不上它。前端用统一请求函数取回文件，生成 `blob:` 地址在新标签页打开，跳页用 `#page=N`（Chromium、Safari 的内置 PDF 阅读器都支持）。S0 认证改为 Cookie 后，换成直接链接。
- 本接口不进 orval 生成的 hooks，前端写一个小函数 `openStandardFile(id, page?)`。
