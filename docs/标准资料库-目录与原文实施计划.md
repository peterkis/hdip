# 标准资料库：标准目录与原文实施计划

依据：建设计划（`docs/标准资料库-建设计划.md`）第 4、6 节；F0 / F1 开发计划、F2 开发计划；Peter 2026-10-31 对标准资料页的意见。

**状态：已实施（2026-11-01），待 PR 审查。** Peter 2026-11-01 把 Drive 资料全部下载到本地，要求“制定标准层的计划并实施落地”，第 9 节的决定按推荐执行，D2 因官网目录已完整取得而扩大为全目录（见第 9 节）。M1、M2 合在一个 PR。本计划插在 F2 第一批与 F2 后续批次、F3 之间。F0–F2 的成果全部保留，不重新导入，也不升级读取器。

## 1 为什么要先补这一层

Peter 的判断：“以权威原始资料及其发布信息为依据，以标准目录为管理入口；在其上关联原文文件、结构化定义和来源关系。PDF 是当前最主要的原文载体，但不是唯一的来源形式。”

现在的页面难读，原因在 F1 的建模，不只是少了几列：

| 现状 | 后果 |
| --- | --- |
| 列表一行是一个 `source_document`，也就是“某个资料包经读取器 vN 处理出的一份结果” | 页面上的单位是处理修订，不是标准。同一标准有 v1、v2 两行，资料包、读取器、覆盖数挤在第一屏 |
| `source_document.title` 有列，但导入命令从未写入（2026-10-31 确认） | 标准没有名称，只能靠编号辨认 |
| 只有被解析过的标准才有行 | 363.1、364.1、364.2 这类没有结构化成果的分册在库里不存在，看不出“缺什么” |
| 发布、实施、废止日期与标准状态都没有登记 | 无法回答“这项标准现在还有效吗” |
| 原 PDF 只是 `source_pdf` 里的一段路径文字 | 打不开原文，也就做不到从定义回到原文 |

可以直接利用的条件：31 份 v2 处理修订（和 2 份 v1）都记录了原 PDF 的 SHA-256（`source_document.source_sha256`），6684 条条目的出处里有 `source_sha256` 与 PDF 物理页。Peter 手上的原 PDF 只要摘要一致，就能确定是同一份文件，**不需要重新解析**。

## 2 范围

**做：**
- 标准目录：一项标准一行（按“标准号 + 年份”），登记名称、发布机构、发布 / 实施 / 废止日期、状态及核实依据。目录信息有历史，不覆盖。
- 原文文件：登记本地持有的原件（正式文本、勘误、发布公告、附件、阅读副本），记录大小与摘要，可在浏览器里打开。
- 已有结构化成果按规则挂到目录与原文上，读取时计算，不改 `source_document`。
- 页面以标准为入口：目录列表 → 标准详情（概览 | 原文与附件 | 结构化内容 | 来源与处理记录）；数据元、值域页面显示所属标准，可“查看本条出处”跳到原文页。
- 第一批登记原件层的全部目录记录（1253 条，第 10.1 节）：官网“卫生健康委员会”分类全目录，加 Drive 归档里不在该分类的国家标准等。

**不做：**
- 不重新导入、不升级读取器、不改 `source_document` / `standard_entry` / `standard_reference` 的结构与已有行。条目 ID 与已有链接不变。
- 不解析 PDF 内容（不抽文字、不数页数、不做 OCR），不自建 PDF 阅读器。
- 不做目录的页面编辑、上传页面、Drive 同步、定时抓取官网。
- 不做关系图谱视图、图数据库；不做院内采用、发布与消费（建设计划第 1.1 节）。
- 院内文件本批不登记（模型支持，见第 9 节 D3）。
- 不收补查包里的其他标准、历史版、364.5 文件 A（`标准资料库-值域引用补查.md` 第 3 节）；它们以后按各自来源另批登记目录。

## 3 对象与表（一次迁移，0025）

三张表，都由 `hdip_owner` 创建，`hdip_app` 只有 SELECT；只由本地导入命令用迁移账号写入，与标准资料库其他表相同（CLAUDE.md“例外：标准资料库”）。

### 3.1 `standard_edition` 标准（身份）

一行 = 一项标准的一个版次，如 “WS/T 363.3—2023”。只留身份，登记后不可改。

| 列 | 说明 |
| --- | --- |
| `id` | 永不复用 |
| `series` | `GB` / `GB/T` / `WS` / `WS/T`；国家 / 行业、强制 / 推荐由它推出，不另存 |
| `standard_no` | 标准号，写法与 `source_document.standard_no` 相同（`WS/T 363.3`），以 `series` 开头 |
| `standard_year` | 四位年份文字 |
| `registered_at` | `LOCALTIMESTAMP` |

约束：`UNIQUE (standard_no, standard_year)`；全行受 `hdip_guard_update()` 保护。WS 与 WS/T 写法不同算两项（官网目录本身就有同号同年两种写法的，第 10.1 节）。

院内文件没有标准号（第 9 节 D3），以后收入时再定身份写法，本批不预留列。

### 3.2 `standard_edition_version` 标准的目录信息（只追加）

沿用 HDIP“身份 + 版本”的写法：目录信息每改一次追加一行，最新一行即当前信息，旧行保留。这里的“版本”是目录记录的修订，**没有业务有效期**，不用 `valid_from / valid_to`。

| 列 | 说明 |
| --- | --- |
| `edition_id` / `seq` | → `standard_edition`；第几次登记，从 1 起，`UNIQUE (edition_id, seq)` |
| `title` | 中文名称，官网目录写法；不在官网分类的取 Drive 归档记录 |
| `catalog_code` | 官网目录里的写法（如 `WS/T 118-1999`），原样；不在官网分类为空 |
| `catalog_category` | 官网分类（数据元目录、数据集标准、其他…），原样 |
| `status` | 官网状态：`CURRENT` 现行（含官网“即将实施”）/ `ABOLISHED` 废止；**空 = 待核实** |
| `issued_on` / `effective_on` | 发布（批准）日期 / 实施日期，官网原样；不检查先后（官网有实施早于批准的记录，如 WS 259—2015） |
| `abolished_on` | 废止日期，选填：官网目录不给废止日期，找到通告时再登记 |
| `verified_on` | 状态与日期的核实日期；`status` 非空时必填 |
| `basis_url` / `basis_note` | 核实依据：官网详情页地址，及说明（“全国标准信息公共服务平台目录 2026-10-30”）；`status` 非空时至少一项 |
| `online_url` | 官网在线阅读地址，选填 |
| `difference` | 官网目录与文件不一致的类别（第 10.1 节，原样），空 = 没有发现 |
| `file_identity` | 文件内标识：封面写法与目录不同时记下（如“封面 WS 192—2008”） |
| `note` | 备注（原件层整理时的说明） |
| `change_note` | 本次登记改了什么，导入命令按差异生成（“首次登记”“改：实施日期、状态”） |
| `recorded_at` | `LOCALTIMESTAMP` |

检查约束：`status` 非空 ⇒ `verified_on` 非空且依据至少一项。全行受保护。

**状态的口径：**
- 库里只记依据官方来源核实到的状态。没有核实的一律“待核实”，**不能因为没填废止日期就当作现行**，也不按下载文件名里的“现行”判断。不在官网分类的标准（Drive 归档的国家标准等）本批都是待核实。
- “即将实施”不存，读取时推算：`status = CURRENT` 且 `effective_on` 晚于今天。官网的“即将实施”登记为 `CURRENT`，到实施日自然变成现行。
- 页面同时显示核实日期，如“现行 · 核实于 2026-10-30”。

### 3.3 `standard_file` 原文文件

一行 = 原件层里挂在某项标准下的一个文件。同一标准可以有多份（364.5 的文件 A / B；WS/T 90—2017 官网列两次、两份字节不同）。

| 列 | 说明 |
| --- | --- |
| `id` | 页面与接口只用 id，不暴露服务器路径 |
| `edition_id` | → `standard_edition` |
| `role` | `TEXT` 正文 / `BOUND` 合订（多项内容装在一个文件里，备注页码范围） / `ERRATA` 修改单与勘误 / `PAGE_IMAGE` 原页图 / `ORIGINAL_FORMAT` 官方原格式（DOCX） |
| `source` | 从哪里取得：“官网下载” / “Drive 归档 03”…，原样。与 `role` 分开，“来自官网”不等于身份已核对 |
| `identity_check` | 与官网目录一致 / Drive 已核对封面 / 未逐份核对封面 / 前缀不同… / 错链… / 待核（第 10.1 节，原样） |
| `page_image` | 是否单页页图（完整性；页图全套与否记在目录备注） |
| `stored_path` | 相对 `HDIP_STANDARDS_DIR` 的路径，须在 `originals/` 下 |
| `file_name` | 归档文件名（保留原文件名；同目录重名时加 `__2`） |
| `media_type` | 按扩展名：`application/pdf`、`image/gif`、DOCX |
| `bytes` / `sha256` | 登记时按本地文件核对；`sha256` 64 位小写十六进制 |
| `note` | 原件层备注（如合订页码范围、封面核对说明） |
| `registered_at` | `LOCALTIMESTAMP` |

约束：`UNIQUE (stored_path)`、`UNIQUE (edition_id, sha256)`、`bytes > 0`；全行受保护。没有标准号的 6 份“相关资料”（`originals/_相关官方资料/`）本批不登记。取得记录（一个文件的多个官网 / Drive 入口，`sources.csv`）本批不入库，留在原件层目录里。

### 3.4 已有成果怎样挂上（读取时计算，不建表）

挂接是确定的，没有需要人裁决的情形，所以不建挂接表：

| 挂接 | 规则 |
| --- | --- |
| 处理修订 → 标准 | `source_document` 的 `standard_no + standard_year` 与 `standard_edition` 完全相同 |
| 处理修订 → 原文文件 | `source_document.source_sha256` 与该标准下某个 `standard_file.sha256` 相同 |
| 条目 → 原文页 | 条目所在处理修订挂上了文件，且条目出处有 `pdf_pages`，跳到第一个物理页 |

- 只按摘要认同一份文件。**A 文件的页码不拿到 B 文件里跳**，即使标准号、年份都相同（如 364.5 文件 A / B）。
- 处理修订找不到标准时，页面说“目录未登记该标准”；找到标准、但没有摘要相同的文件时，说“未登记本条所据的原文（摘要 `xxxx…`）”，不给页码跳转。
- 以后若遇到标准号写法不同、要人工指定的情形，再加挂接表。

## 4 目录怎样维护：原件层生成的目录 + 导入命令

目录不手写：`api/scripts/originals_build.py` 从官网目录快照与 Drive 归档清单生成 `hdip-standards/catalog/editions.csv`、`files.csv`（第 10.1 节），导入命令读这两份。官网快照、Drive 清单原样存在 `catalog/` 里，同样的输入重跑得到同样的目录。

命令 `api/scripts/import_catalog.py`（迁移账号）：
- `--check`：读两份 CSV 与本地文件，打印将要新增的标准、追加的目录版本、登记的文件，以及全部问题，不写库。
- 不带参数：在一个事务里写入；任何一行有问题就整体回滚，报“文件:行号 列名：原因”。
- 规则：
  - 新标准 → 身份 + 第 1 版；已有标准的目录字段变了 → 追加一版并写明改了哪些字段；没变 → 不写。重复执行不增行。
  - CSV 里少了已登记的标准或文件 → 拒绝（库里不删）。
  - 文件：路径须在 `originals/` 下、存在、大小与摘要和 CSV 一致；已登记的文件信息变了 → 拒绝（本批不支持改）。
  - 日期 `YYYY-MM-DD`；状态按第 3.2 节映射，官网状态以外的写法拒绝。
  - 只读本地文件、不执行、不解压；PDF 只算摘要，不解析。
- 以后要人工更正某项（如找到废止通告补废止日期、核实 WS/T 587 的年份），再加一份入库的更正表（`data/standards/catalog-overrides.csv`）叠在生成的目录上；本批没有这种更正，不建。

## 5 原文的读取

- `GET /api/standards/files/{id}/content`，权限 `standard.view`（第 9 节 D4）。按 id 找到 `stored_path`，解析后必须仍在 `HDIP_STANDARDS_DIR/originals` 下；比对大小（不每次重算摘要，建设计划第 6.1 节），不一致或文件不在时返回 404 并说明“原文文件不在资料目录 / 已变动”。响应按 `media_type`，`Content-Disposition: inline`（带原文件名）。
- 现在的开发期身份放在请求头 `X-HDIP-User`，浏览器直接打开接口地址带不上它。前端用 `fetch` 取回文件（`lib/standard-file.ts`，不用 orval 生成的函数：统一请求函数按文本读响应，会损坏二进制），生成 `blob:` 地址，在**应用内原文页**`/standards/library/editions/:id/files/:fileId?page=N` 用内嵌框显示，PDF 跳页用 `#page=N`；官方原格式 DOCX 浏览器不能显示，只给下载。不弹新窗口：异步取回后再开窗口会被拦截，内嵌浏览器也不允许顶层打开 `blob:` 地址（2026-11-01 实测）。S0 认证改为 Cookie 后可换成直接链接。

## 8 落地顺序

#### 身份怎样认定

- **官网目录条目是入口**，文件封面是证据，不是最终身份。目录写法与封面写法都保留；存放路径只是位置，不代表身份。
- 文件只在一种情形下归到别的标准目录：官网入口返回的是**另一个标准号**（错链），且 Drive 归档已核对封面。此时文件挂到封面那项标准，**错误入口的状态、日期不随文件转移**，入口记录保留在 `sources.csv`。
- 封面与目录只差 WS / WS/T 前缀，或年份、名称不同：文件留在目录条目下，记下“文件内标识”，不另造版次。
