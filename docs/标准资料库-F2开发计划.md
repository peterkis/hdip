## 2 已对齐的决定（2026-10-29）

### 2.1 引用只在同一处理修订里解析

读取器版本是本系统的处理修订，不是标准版本。

**解析范围。** `value_domain` 引用只在来源条目自己的范围里找目标：同一 `source_package`、`family`、`reader`、`reader_version`。然后按标准号、年份、值域编号查找。
- v1 的数据元只解析到 v1 的值域，v2 只解析到 v2。
- v1 与 v2 不互相成为候选。
- 本范围里找不到目标，结果就是 unresolved，不回退到其他修订。其他修订里有同标识条目时，只作阅读提示（`related.kind = other_revision`）。
- 外部规范引用本期不做跨资料族解析。

**当前处理修订。** 在“包 + 资料族 + 读取器 + 标准号 + 原文年份”范围内，读取器版本最高的一份就是当前处理修订。
- 版本按十进制整数比较，所以 v10 高于 v2。
- 查询时动态计算，不存字段。
- 列表与检索默认只给当前处理修订；`include_superseded=true` 或页面上的“显示历史处理修订”可以显示全部。
- 历史处理修订按 id 仍可打开，页面提示“存在更新的处理修订 vN”，不说成“新版标准”。
- 不同来源包分别展示，不自动决定哪个包优先。

### 2.2 WS 与 WS/T 前缀差异：精确优先，受限回退

`target_standard` 与 `raw_text` 都保留原文写法（例如 `WS 364.16`），不在导入时改写。

解析先做精确匹配，这时 WS 与 WS/T 算不同的前缀。只有同时满足以下条件，才回退到同分册的 `WS/T 364.x`：
- 精确匹配结果为 0；
- 来源条目属于 `ws363-364` 资料族的 WS/T 363.x—2023；
- 引用写作 `WS 364.x`；
- 目标与引用的分册编号一致，值域编号也一致；
- 目标在同一处理修订范围里。

回退后的结果：
- `resolution = catalog`，`match_basis = prefix_variant`，另附 `resolution_note`，例如：“来源写作 WS 364.16；本库按已知标准前缀差异定位到 WS/T 364.16—2023。原文未写年份。”
- 结果不是 explicit，页面也不说 WS 与 WS/T 等价。
- 回退候选有多个时，结果是 candidates，不自动选择。
- 回退目标的名称明显不一致（`label_check = different`）时不回退，结果是 unresolved，目标另列为阅读提示（`prefix_variant_conflict`）。

这条规则不推广到 GB 与 GB/T、其他系列、其他年份、其他来源包或其他读取器版本。

### 2.3 跨分册的同编号表只作阅读提示

引用所指的分册里没有该 CV 时，结果是 unresolved，即使其他分册有同编号、同名的表也一样。其他分册的同编号表只列为阅读提示：“引用分册中未找到该值域；本库其他分册存在同编号表，仅供参考。”（`related.kind = other_part`）

阅读提示不能借前缀归一、同编号或同名升级为解析结果。

### 2.4 名称不同：两个名称都显示，解析结果不变

`resolution` 只说明编号在范围里有没有找到。每个目标另附 `label_check`，比较时先去掉空白：

| 取值 | 含义 | 页面显示 |
| --- | --- | --- |
| `same` | 名称一致 | 不提示 |
| `minor` | 只差末尾的“代码”“表”等 | 低强度提示“名称写法不同” |
| `different` | 主体名称不同，或无法可靠判断 | 来源引用名称与本库表名称并列，标“名称不一致 · 待核对”，解析标签改为灰色的“按编号定位” |

`different` 还会写明“编号可定位，但来源名称与目标表名称不一致，语义尚未确认”，不用成功色。

不做相似度计算或语义匹配。DE05.10.094.00 不做特别处理，按这条通用规则显示。

## 3 读取器 v2 改了什么（`ws363-364@2`）

| 项 | v1 | v2 |
| --- | --- | --- |
| 值域编号（B1） | 遇到空格就截断，例如 `CV04. 10. 018` 记成 `CV04` | 只认完整的 `CVdd.dd.ddd`。点的两侧、前两段数字之间允许排版空白，末段三位必须连写，免得把表名开头的数字并进编号。编号不完整时目标标识留空、不补全。原文保留在 `raw_text`，读取时给出 `identifier_as_written` 与 `identifier_normalized` |
| `source_issues` 里的对象（D） | `str()` 成 Python 字面形式 | 保留对象结构；页面按“键：值”显示 |
| `raw_cells` 里的 null（D） | 存成字符串 `"None"` | 保留为 null；页面显示“（未提供）” |
| `qa_evidence.source_images`（D） | 不读 | 与 `image_paths`（或 `pages`）合并去重；按包成员核对可用性，包里没有就是“未随包提供” |

只影响出处与正文的写法，不改条目身份。v1 的 15 条条目原样保留，不回写，也不要求与 v2 输出相同。

## 4 接口与页面

**接口（契约已重新生成，`make gen`）：**
- `GET /api/standards/documents?include_superseded=`：每行加 `series`、`is_current`、`newer_revision`。
- `GET /api/standards/documents/{id}`：加 `revisions`，列出同一来源文档的全部处理修订。
- `GET /api/standards/entries`：
  - 参数：`q`、`entry_type`、`top_level`、`document_id`、`series`、`standard_no`、`standard_year`、`include_superseded`、`offset`、`limit`（最多 200）。
  - 返回 `{items, total, offset, limit}`。筛选全部在计数与分页之前完成，`total` 是匹配总数。
  - 排序稳定：标准号自然序（363.2 在 363.10 之前）→ 文档 → 类型 → 原顺序 → id。
  - 代码行附所属值域表（`parent`）。
  - 指定 `document_id` 时就看那一份，包括历史处理修订。
- `GET /api/standards/entries/{id}`：
  - 加 `newer_revision`。
  - 引用加 `match_basis`、`resolution_note`、`identifier_as_written` / `_normalized` / `_incomplete`、`related`，目标加 `label_check`。
  - 被引用的条目加 `match_basis`、`label_check`。

**页面：**
- **数据元**（`/standards/data-elements`）：可按名称或 DE 检索，按标准、分册、原文年份筛选，服务端分页。筛选写在网址里，检索词与页码从详情返回时恢复，集合条件一变就回到第一页，翻页回到列表顶部。
- **值域与代码**（`/standards/value-domains`，新入口）：分“值域表 / 代码”两个标签。
  - 值域表按名称或 CV 检索。
  - 代码按码值或名称检索，结果带所属值域表与标准，不同表的相同码值各占一行。
- **标准资料**：
  - 默认只列当前处理修订，可打开“显示历史处理修订”。
  - 详情列出各处理修订，历史修订有提示。
  - 已接入的条目改为服务端只取顶层条目再分页，不再先取 500 条混合类型、再在前端去掉代码行。
- **条目详情**：
  - 页头写明“读取器 vN · 当前 / 历史处理修订”。
  - 引用分别显示解析结果、定位依据、名称比较和阅读提示。
  - 资料记载的问题与原单元格按第 3 节显示。
