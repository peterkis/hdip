### 发现的问题与处理（三分法）

1. **操作不顺（已修）**：取回草稿时，修订项里没改的字段以 null 返回；页面往这张草稿再加一项时把 null 原样回传，被当成“清空”。部门修订报“设立形式不能清空”；单元修订可能把电话、范围说明静默清空（确认页能看到，但容易漏看）。改为申请接口只返回填写过的字段，并加了回归测试。
2. **操作不顺（已修）**：拆分 / 合并的申请页没有前后对照（表格为空）。改为逐行列出前身与后继的单元、类型、部门、院区、运营主体；单元快照加了代码。
3. **操作不顺（已修）**：部门页只能设管理主分类，不能按其他分类方案（如病案科室分类）赋值；分类方案页不能登记方案、不能写“用于部门 / 单元时的含义”。补了部门“其他分类”、通用分类表单、方案的登记与编辑。
4. **系统表达不了（已修）**：可多选的分类方案无法结束一条已有分类。新增变更项 `department.classification_close` / `service_unit.classification_close`（迁移 0009 只加确认规则）。
5. **操作不顺（已修）**：合并时可选的前身按今天列出，含合并日之前已退出的单元。改为列出生效日前一天仍有效的单元，生效日放在前面先填。
6. **操作不顺（已修）**：调整上级时，排除的“下级”按查看日期计算，按生效日会成环的部门仍可选（提交时才被拒）。改为按生效日计算。
7. **操作不顺（已修）**：来源系统窗口里第一次登记字典时，来源系统看似已选、实际为空，保存报“请选择来源系统”。只有一个来源系统时直接选中。
8. **操作不顺（已修）**：改挂部门时如果没有其他部门，下拉框为空且没有提示。补了说明：先新建部门存草稿，再选这张草稿。
9. **小问题（已修）**：变更运营状态的标题显示院区代码，改为名称；详情页地址无效时空白，改为提示。
